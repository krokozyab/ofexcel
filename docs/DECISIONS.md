## Р1. DuckDB 2.0 (альфа) вместе с ofquack 0.4.x

**Решение.** Продукт собирается на DuckDB `b15358c3` (`v2.0.0-alpha46057`) и ofquack `15be8cc` (0.4.1) — на тех же фиксациях, что основная ветка ofquack.

**Почему.** ofquack развивается на 2.0, а ветка 1.5 (ofquack 0.3.1) только поддерживается. Если взять стабильную 1.5.6, придётся либо держать ofquack на старой ветке, либо поддерживать две.

**Последствия.**
- Внутренний C++ API DuckDB между альфами меняется. Мы уже видели это на объявлении именованных параметров табличных функций.
- Три фиксации двигаются **только вместе** и только по отдельной задаче: сабмодуль `duckdb`, `duckdb_version`/`duckdb_tag` в `.github/workflows/ci.yml` и `GIT_TAG` ofquack в `extension_config.cmake`.
- Перед обновлением DuckDB сначала обновляется и проверяется ofquack.

**Пересмотреть, если:** вышла стабильная 2.0; очередная альфа ломает сборку так, что починка дороже перехода на 1.5; ofquack перестаёт поддерживать 2.0.

## Р2. Время из Oracle `DATE` — только через `CAST(col AS TIMESTAMP)`

**Решение.** Модель данных SQL-отчёта (`DM_ARB`) не меняется. Колонка Oracle `DATE` приходит как `YYYY-MM-DD`, и время суток в ней теряется. Автору, которому нужно время, следует писать в запросе `CAST(col AS TIMESTAMP)`.

**Почему.** Отчёт остаётся стандартным для ofquack и не требует отдельной настройки на каждом инстансе. Колонки, где время важно больше всего (`CREATION_DATE`, `LAST_UPDATE_DATE`), в Fusion имеют тип `TIMESTAMP` и время сохраняют.

**Последствия.**
- Потеря времени — **тихая**: по значению `2026-10-29` нельзя понять, было ли в исходной колонке время.
- `CONTRACTS.md` §3.3 описывает это как постоянное правило, требование Q6 к ofquack снято (§15).
- Редактор SQL и Preview показывают у колонок типа `date` из Oracle-запроса подсказку: "Oracle DATE columns come without the time of day. To keep the time, use CAST(column AS TIMESTAMP)".
- Правило в документации для авторов запросов, вместе с примером.
- Примеры запросов, которые поставляются с продуктом, используют `CAST(… AS TIMESTAMP)` везде, где время имеет смысл.

**Пересмотреть, если:** пилоты покажут, что авторы регулярно получают неверные данные из-за этого правила. Тогда возвращаемся к варианту «исправить формат даты в модели данных отчёта».

## Р3. Без процесса `worker` в MVP

**Решение.** Oracle-запуски в MVP выполняются в процессе демона. Отмена — `Connection::Interrupt()`.

**Почему.** Фаза 0 показала: прерывание останавливает даже идущий сетевой запрос за 0,2–0,3 с, и соединение после этого работает.

**Последствия.** Роль `ofexceld worker` переносится в фазу 2 — только для изоляции недоверенных определений Local SQL. `SPEC.md` §7.6 и §16 уже обновлены.

**Пересмотреть, если:** появятся зависания, которые прерывание не снимает (например, на стороне TLS или DNS), или ошибки памяти в долгих заданиях начнут ронять демон.

## Р4. Предел строк по умолчанию — 1 000 000, с видимым прогрессом

**Решение.** `@max_rows` по умолчанию остаётся 1 000 000 для вывода в таблицу и 10 000 для `OF.TABLE` (`CONTRACTS.md` §5.4).

**Почему.** При ~5 200 строк/с миллион строк загружается примерно за 3,2 минуты. Это долго, но допустимо, если пользователь видит, что происходит.

**Последствия.**
- Во время запуска панель показывает число полученных строк, скорость и прошедшее время, а затем время записи на лист.
- **Оценки оставшегося времени нет:** общий объём результата заранее неизвестен, а отдельный `COUNT(*)` стоит лишнего запроса (1–3,5 с) и не всегда дешёв на стороне Oracle.
- Кнопка "Cancel" доступна всё время запуска.

**Пересмотреть** после замера записи в Excel Table (фаза 0, проверка 5): если запись миллиона строк окажется неприемлемо долгой, предел снижается.

## Р5. Вход через SSO не блокирует интерфейс

**Решение.** Вход через SSO занимает 17–120 с, токен живёт около 4 часов. Панель показывает состояние входа и не блокирует остальной интерфейс.

**Последствия.**
- `POST /v1/auth/login` выполняется до 300 с (`CONTRACTS.md` §8.3). Панель вызывает его асинхронно и тем временем показывает "Signing in to Fusion — finish in the browser window that opened" с прошедшим временем.
- Пока вход идёт, работают редактор, импорт, Local SQL и чтение уже полученных данных. Недоступны только запуски Oracle-запросов на этом подключении.
- Когда до истечения токена остаётся меньше 15 минут, панель предупреждает. Если токен истёк посреди обновления, запуск завершается с `E_FUSION_AUTH` и кнопкой "Sign in again".

**Пересмотреть, если:** в ofquack появится тихое обновление токена без браузера.

## Р6. API демона — только HTTPS с локальным CA

**Решение.** Демон отвечает только по HTTPS на `127.0.0.1:<port>`, с сертификатом от локального CA, в обоих профилях. Профиль определяет только, откуда берётся статика надстройки:
- **hosted** — HTTPS-хостинг (интранет, CDN); запросы к демону идут с другого источника через CORS. Профиль по умолчанию для корпоративного развёртывания, манифест проходит Centralized Deployment;
- **local** — статику отдаёт сам демон, тот же источник. Для офлайна и разработки.

**Почему.** Зонд в Excel для Mac показал: WebView не делает запросов с HTTPS-страницы на `http://127.0.0.1` и `http://localhost`, запрос обрывается до сети. HTTPS на loopback с доверенным сертификатом работает с того же источника и с другого, включая CORS preflight (`PHASE0_REPORT.md` §4.8). Прежний замысел «hosted без своего CA» на Mac невозможен.

**Последствия.**
- Установщик ставит локальный CA в доверенные текущего пользователя (связка ключей входа на Mac, `CurrentUser\Root` на Windows) без прав администратора, либо CA раскатывает IT через MDM. Подробности — `SPEC.md` §12.4.
- `CONTRACTS.md` §8.1: база API — HTTPS в обоих профилях. `SPEC.md` §5.1, §8.5, §12.3, §12.4 и таблица рисков обновлены.
- **Каркас пока отвечает в профиле hosted по HTTP**, а профиль local отклоняет с `E_UNSUPPORTED`. TLS в демоне — отдельная задача: генерация CA и сертификата (`ofexceld install-cert`), HTTPS-сервер (cpp-httplib с OpenSSL), установка CA в доверенные.
- Риск «корпоративная ИБ не пропускает локальный CA» остаётся. Смягчения — CA с name constraints только на `localhost` и `127.0.0.1`, раскатка через MDM, серверный режим (`SPEC.md` §13).

**Пересмотреть, если:** WebView2 под Windows поведёт себя иначе (проверка в конце разработки); Office начнёт пускать HTTPS-страницы к HTTP на loopback; появится серверный режим, где локальный демон не нужен.

## Р7. Сообщения продукта и интерфейс — на английском

**Решение.** Всё, что видит пользователь продукта, — на английском:
- тексты ошибок (`message` в ответах API, сообщения исключений SQL-функций);
- предупреждения запусков, ошибки разбора файлов запросов, вывод `ofexceld` в stdout и stderr;
- интерфейс надстройки Excel и подсказки в нём.

Коды ошибок (§14) не меняются. Документация проекта (`SPEC.md`, `CONTRACTS.md`, `TASKS.md`, этот журнал) остаётся на русском. Тексты сообщений, которые контракт приводит дословно, приводятся на английском.

**Почему.** Решение владельца продукта.

**Последствия.**
- Существующие сообщения переведены. Тесты сверяют английские тексты.
- В новом коде сообщения сразу пишутся на английском.

**Пересмотреть, если** понадобится локализация. Тогда сообщения выносятся в каталог строк, а английский остаётся языком по умолчанию.
