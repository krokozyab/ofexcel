## 0. Как читать этот документ

- Это **нормативный** документ для реализации MVP. `SPEC.md` объясняет, зачем и почему; здесь — точные форматы, правила и ожидаемые результаты.
- При расхождении с `SPEC.md` для MVP действует этот документ. Найденное расхождение — повод исправить один из документов, а не выбирать по ситуации.
- Слова **ДОЛЖЕН**, **НЕ ДОЛЖЕН**, **МОЖЕТ** — обязательность, как в RFC 2119.
- Пометка **[Ф0]** — допущение, которое проверяется в фазе 0. Пока оно не подтверждено, реализация следует этому документу, а при опровержении документ меняется до того, как меняется код.
- Тестовые векторы в таблицах — **приёмка**. Каждый вектор ДОЛЖЕН стать автоматическим тестом. Реализация, не проходящая вектор, не готова, даже если «по смыслу правильная».
- Всё, чего здесь нет и нет в объёме MVP (`SPEC.md`, блок «Объём MVP»), реализовывать НЕ НУЖНО. Если без этого задачу не сделать — остановиться и спросить.

## 1. Общие соглашения

| Тема | Правило |
|---|---|
| Кодировка | UTF-8 везде: файлы, HTTP, JSON, SQL-тексты |
| Время в метаданных | UTC, тип DuckDB `TIMESTAMP`; в JSON — строка `YYYY-MM-DDTHH:MM:SSZ` |
| Идентификаторы запросов, импортов, подключений | `^[a-z][a-z0-9_]{0,62}$` |
| UUID | v4, строка в нижнем регистре с дефисами |
| Хеш | SHA-256, строка из 64 шестнадцатеричных символов в нижнем регистре |
| JSON в DuckDB | Колонки с JSON — тип `VARCHAR` (расширение `json` не линкуется) |
| Порядок ключей | Где нужен канонический JSON — ключи отсортированы по байтам UTF-8, без пробелов. Строки экранируются как в RFC 8785: только `"` → `\"`, `\` → `\\` и U+0000–U+001F (`\b \t \n \f \r`, остальные — `\u00xx` строчными); всё прочее, включая `/`, U+007F и не-ASCII, — байтами UTF-8 как есть. Невалидный UTF-8 — ошибка. Числа — только целые. Реализация — `src/catalog/hashing.cpp` (`CanonicalParams`, `CanonicalJson`) |
| Пути на диске | `QEXCEL_HOME`: macOS — `~/Library/Application Support/QExcel`, Windows — `%LOCALAPPDATA%\QExcel`; переменная окружения `QEXCEL_HOME` заменяет это значение (тесты, нестандартная установка). Каталог создаётся с правами `0700`. В нём: `data.duckdb` — база демона, `init.sql` — конфигурация (если есть), `tls/` — сертификаты (§8.1). Проекты — `~/QExcel/projects/<проект>/queries/*.sql` (Windows — `%USERPROFILE%\QExcel\projects`), каталог заменяет настройка `ofexcel_projects_dir` (§13). Имя проекта — имя его каталога: непустое, до 100 байт UTF-8, без управляющих символов и `/ \ : * ? " < > \|`, не начинается с `.` и не кончается `.` или пробелом; каталоги с другими именами пропускаются. Файл запроса — не больше 1 МБ |

### 1.1 Хеш определения
`definition_hash = sha256(bytes)`, где `bytes` — текст файла запроса после двух преобразований: удалить BOM UTF-8 в начале; заменить `\r\n` и одиночные `\r` на `\n`. Больше никаких нормализаций (пробелы, регистр, комментарии сохраняются).

### 1.2 Канонические параметры
`canonical_params` — канонический JSON-объект `{имя: значение}` по всем параметрам запроса **после** применения значений по умолчанию. Значения — строки в канонической форме типа (§3.1, колонка «Каноническая форма»); `list<T>` — JSON-массив канонических строк в исходном порядке.

### 1.3 Ключ экземпляра dataset'а
```
instance_key = sha256(query_id + "\n" + definition_hash + "\n" + connection_name + "\n" + canonical_params)
```
Для запроса с `@engine: local` в `connection_name` пишется `local`.

## 2. Формат файла запроса

### 2.1 Структура
- **Заголовок** — все строки от начала файла, пока строка (после удаления ведущих пробелов) начинается с `--` или пуста.
- Строка заголовка вида `-- @ключ: значение` — директива: после `--` и пробелов идёт `@` и буква. Двоеточие после ключа можно опустить (`-- @param bu: integer`, как в P4: у `@param` и `@column` двоеточие есть внутри значения). Остальные строки заголовка — комментарии, игнорируются (в том числе `-- @ 10:00`, где после `@` не буква).
- Разбор идёт по тексту после нормализации §1.1 (BOM, концы строк); номера строк в ошибках — те же, что в редакторе. Строка не в UTF-8 — `E_QUERY_PARSE`. Разбор не останавливается на первой ошибке: возвращаются все, по порядку строк, общие для файла (нет обязательной директивы) — первыми, со строкой 0.
- Пустое значение у любой директивы, кроме `@description`, — `E_QUERY_PARSE`.
- **Тело** — всё после заголовка. Тело ДОЛЖНО быть непустым после удаления пробелов и комментариев.
- Ключи директив — в нижнем регистре. Неизвестный ключ — ошибка `E_QUERY_PARSE` (опечатка не должна молча игнорироваться).
- Повтор неповторяемой директивы — `E_QUERY_PARSE`.

### 2.2 Директивы MVP

| Директива | Повтор | Обязательна | Грамматика значения |
|---|---|---|---|
| `@id` | нет | да | идентификатор (§1) |
| `@engine` | нет | да | `oracle` \| `local` |
| `@version` | нет | да | целое `1..2147483647` |
| `@title` | нет | нет | текст до конца строки, ≤ 200 символов |
| `@description` | да | нет | текст; строки объединяются через `\n` |
| `@connection` | нет | нет | имя подключения; только для `oracle` |
| `@param` | да | нет | `имя: тип [= по_умолчанию] [\| описание]` |
| `@column` | да | нет | `ИМЯ: тип_колонки [\| заголовок]` |
| `@depends` | да | нет | только для `local`: `query_id(арг := значение, …)` или `xl_import.имя` |
| `@refresh` | нет | нет | `full`. Значение `incremental(...)` распознаётся и даёт `E_UNSUPPORTED` |
| `@max_rows` | нет | нет | целое `1..1048575` |

Грамматика (EBNF, пробелы между лексемами допускаются):
```
param      = name ":" ptype [ "=" default ] [ "|" text ] ;
ptype      = "integer" | "number" | "decimal(" int "," int ")" | "string" | "id"
           | "date" | "timestamp" | "boolean" | "enum(" word { "," word } ")"
           | "list<" scalar_ptype ">" ;
scalar_ptype = любой ptype, кроме list и enum ;
default    = '"' { любой символ, '\"' — кавычка } '"' | текст до "|" или конца строки (обрезается) ;
column     = colname ":" ctype [ "|" text ] ;
colname    = [A-Za-z][A-Za-z0-9_$#]* ;          (сравнивается без учёта регистра)
ctype      = "id" | "integer" | "decimal(" int "," int ")" | "number" | "string" | "text"
           | "date" | "timestamp" | "timestamptz" | "boolean" ;
depends    = query_id "(" [ dep_arg { "," dep_arg } ] ")" | "xl_import." name ;
dep_arg    = name ":=" ( "$" name | literal ) ;
literal    = "'" текст_с_удвоением_кавычки "'" | число | "DATE '" YYYY-MM-DD "'" | "TRUE" | "FALSE" ;
word       = [A-Za-z0-9_]+ ;
```
- Имена параметров — идентификаторы (§1): только нижний регистр, поэтому у имени одно написание, и ключи `canonical_params` однозначны. В SQL `:BU` всё равно сопоставляется с `@param bu` без учёта регистра (§4.1).
- Имена типов — в нижнем регистре; варианты `enum` — с сохранением написания и уникальны без учёта регистра.
- `decimal(p,s)`: `1 ≤ p ≤ 38`, `0 ≤ s ≤ p`.
- Значение по умолчанию проверяется по типу при разборе (§3.1, ввод строкой) и хранится в канонической форме; неверное — `E_QUERY_PARSE`. Пустая строка по умолчанию пишется `""`; `=` без значения — ошибка.
- **Значение по умолчанию для `list<T>`** — элементы через запятую, каждый обрезается и проверяется по `T`: `@param ids: list<id> = 1, 2, 3`. `= ""` — пустой список. Элемент со своей запятой так не записать.
- `@depends`: `$имя` ДОЛЖЕН быть объявлен в `@param` этого запроса; имена аргументов не повторяются; запрос не может зависеть от самого себя. Ключевые слова `DATE`, `TRUE`, `FALSE` — без учёта регистра.
- `@param` и `@column` объявлены в том порядке, в котором записаны; порядок `@param` — это порядок позиционных аргументов формул (§10).

## 3. Типы

### 3.1 Типы параметров

| Тип | Что принимается на входе (JSON от панели) | Каноническая форма | Отказ |
|---|---|---|---|
| `integer` | число без дробной части, \|x\| ≤ 2^53; строка `^-?[0-9]{1,38}$` | `-?[1-9][0-9]*` или `0` | дробь, экспонента, пусто |
| `number` | число; строка десятичной записи без экспоненты | кратчайшая запись, обратимая в double, в формате `std::to_chars` (фиксированная или научная — что короче, при равенстве фиксированная: `0.001`, `1e-04`, `1e+20`); `-0` → `0` | NaN, ±Inf, экспонента в строке, переполнение double |
| `decimal(p,s)` | число; строка `^-?[0-9]*(\.[0-9]*)?$` с хотя бы одной цифрой | без ведущих нулей (кроме `0`), без лишних нулей дробной части, `-0` → `0` | как `DECIMAL(p,s)` в SQL: больше `p − s` цифр до точки или больше `s` после неё (хвостовые нули дробной части не считаются). `decimal(5,2)`: `999.99` — да, `1234.5` — нет |
| `string` | строка; число или boolean → строка в канонической форме их типа | строка как есть | NUL и символы C0, кроме TAB/LF/CR; длина > 4000 байт UTF-8 |
| `id` | строка `^[0-9]{1,38}$`; число без дробной части ≤ 2^53 | цифры без ведущих нулей (кроме `0`) | иное |
| `date` | строка `YYYY-MM-DD` | `YYYY-MM-DD` | несуществующая дата |
| `timestamp` | строка `YYYY-MM-DD[ T]HH:MM:SS[.f{1,6}]` | `YYYY-MM-DD HH:MM:SS[.ffffff]` (дробь — только если ненулевая, без хвостовых нулей) | иное |
| `boolean` | `true`/`false`; строки `Y/N`, `TRUE/FALSE`, `1/0` без учёта регистра | `true` / `false` | иное |
| `enum(…)` | строка, совпадающая с вариантом без учёта регистра | вариант в написании из объявления | не из списка |
| `list<T>` | JSON-массив элементов `T` | массив канонических форм | любой элемент не проходит `T`; больше 100 000 элементов |

- **Даты из Excel приходят строками.** Панель ДОЛЖНА превращать серийные даты Excel в `YYYY-MM-DD` / `YYYY-MM-DD HH:MM:SS` сама, с учётом системы дат книги (1900 или 1904). Демон серийных дат не принимает.
- **Пустое значение** (`null`, `""`, отсутствие ключа) → значение по умолчанию; если его нет — `E_PARAM_MISSING`. Для `list<T>` пустой массив `[]` — это значение, а не пустота.
- **Коды отказа:** строка длиннее 4000 байт и список больше 100 000 элементов — `E_PARAM_TOO_LONG`; всё остальное — `E_PARAM_TYPE`.
- **Число JSON** приходит демону своим текстом, без потерь. Для `integer` и `id` принимается целое по значению (`1.0e3` → `1000`) в пределах ±2^53, для `id` — неотрицательное. Для `decimal` берутся цифры как записаны, а не double (`0.1` остаётся `0.1`; экспонента раскрывается). Для `date`, `timestamp`, `boolean`, `enum` число не принимается.
- **Элементы `list<T>`:** `null` — `E_PARAM_TYPE` с номером элемента; `""` — значение (его примет `list<string>`, остальные типы откажут). Вложенный массив — отказ.
- Реализация: `src/catalog/param_values.cpp` (JSON) поверх `src/catalog/contract_types.cpp` (ввод строкой, канонические формы).

### 3.2 Типы колонок результата

| Тип | Хранение в DuckDB | JSON (демон → панель) | Запись в Excel |
|---|---|---|---|
| `id` | `VARCHAR` | строка | строка; формат колонки `@` |
| `integer` | `BIGINT` | число | число |
| `decimal(p,s)` | `DECIMAL(p,s)` | **строка** в канонической форме `decimal` | `Number(строка)` |
| `number` | `DOUBLE` | число; NaN/±Inf → `null` + предупреждение запуска | число |
| `string` | `VARCHAR` | строка | строка; формат колонки `@` |
| `text` | `VARCHAR` | строка | строка ≤ 32 767 символов (длиннее — усечение, §11.4); формат `@` |
| `date` | `DATE` | `YYYY-MM-DD` | серийная дата |
| `timestamp` | `TIMESTAMP` | `YYYY-MM-DD HH:MM:SS[.ffffff]` | серийная дата-время |
| `timestamptz` | `TIMESTAMP`, приведённый к UTC | `YYYY-MM-DDTHH:MM:SS[.ffffff]Z` | серийная дата-время UTC; к заголовку добавляется ` (UTC)` |
| `boolean` | `BOOLEAN` | `true`/`false` | `TRUE`/`FALSE` |
| любой, значение NULL | `NULL` | `null` | пустая ячейка |

### 3.3 Определение типов колонок Oracle-результата
Результат Oracle-запроса приходит **строками** (`all_varchar := true`, §5.1): типы Oracle недоступны, потому что `dbms_xmlgen` отдаёт текст. Тип каждой колонки определяется демоном **по полному результату**, а не по первой странице.

**Пустая строка — это NULL.** Ofquack в режиме `all_varchar` отдаёт NULL пустой строкой (`PHASE0_REPORT.md` §4.2). В Oracle `''` и NULL неразличимы, поэтому для Oracle-результатов демон ДОЛЖЕН заменить `''` на NULL **до** всех шагов ниже — и в выводе типов, и в сохранённых значениях. Для Local-результатов замена не делается: DuckDB различает `''` и NULL.

Для каждой колонки:
1. Если колонка объявлена `@column` — тип из объявления. Если хоть одно ненулевое значение не приводится к нему — запуск падает с `E_TYPE_DECLARED_MISMATCH` (в сообщении: колонка, номер строки, значение).
2. Иначе, если в схеме запроса (`meta.query_schemas`, §6.2) для этого `definition_hash` уже есть тип — он берётся как стартовый и **может только расширяться** (п. 4).
3. Иначе тип выводится по значениям (NULL пропускаются):

   | Условие на все ненулевые значения | Тип |
   |---|---|
   | значений нет (все NULL или 0 строк) | `string` |
   | все — целые без ведущих нулей `^-?(0\|[1-9][0-9]*)$`, и (имя колонки оканчивается на `_ID` без учёта регистра **или** хоть одно значение длиннее 15 цифр) | `id` |
   | все — целые без ведущих нулей, длина ≤ 15 цифр | `integer` |
   | все — числа `^-?(0\|[1-9][0-9]*)?(\.[0-9]+)?$` с хотя бы одной цифрой (в т. ч. `.84`, `-.5`), и `max(цифр целой части) + max(масштаб) ≤ 38` | `decimal(38, max(масштаб))` |
   | то же, но больше 38 цифр | `number` + предупреждение |
   | все — `YYYY-MM-DD` | `date` |
   | все — `TS` и у всех время `00:00:00` с нулевой дробью | `date` |
   | все — `TS` | `timestamp` |
   | все — `TSTZ` | `timestamptz`, значения приводятся к UTC |
   | иначе (в т. ч. смесь `TS` и `TSTZ`) | `string` |

   Здесь `TS` — `^YYYY-MM-DD[ T]HH:MM:SS(\.[0-9]{1,9})?$`, `TSTZ` — то же с суффиксом `±HH:MM` (пробел перед знаком необязателен). Дробь до 9 знаков допускается, потому что Oracle `TIMESTAMP` отдаёт до 9 знаков. Хранится с точностью до микросекунд: знаки с 7-го по 9-й **отбрасываются**, а не округляются.

   Тип `text` автоматически не выводится (только объявлением), `boolean` — тоже.
4. **Расширение типа.** Если стартовый тип (п. 2) не вмещает новые значения, он расширяется по цепочкам: `integer → decimal → number → string`, `id → string`, `date → timestamp → string`, `timestamptz → string`; переход между цепочками — сразу в `string`. Расширение пишется в `meta.query_schemas` и в предупреждения запуска (`W_TYPE_WIDENED`). Сужение не делается никогда. Предупреждение о типе `number` для числа длиннее 38 цифр (п. 3) — `W_NUMBER_PRECISION`.

**Что значит «тип вмещает значение»** (для п. 1, п. 2 и п. 4):

| Тип | Вмещает |
|---|---|
| `id` | целое без ведущих нулей, любой длины |
| `integer` | целое без ведущих нулей, ≤ 15 цифр |
| `decimal(p,s)` | число `^-?(0\|[1-9][0-9]*)?(\.[0-9]+)?$`: ≤ `p − s` цифр до точки, ≤ `s` после (хвостовые нули не считаются — так же считается и масштаб в п. 3) |
| `number` | то же число любой длины; объявленный `@column … number` — ещё экспоненту, `Inf`, `NaN` |
| `date` | `YYYY-MM-DD` или `TS` в полночь с нулевой дробью |
| `timestamp` | `YYYY-MM-DD` (полночь) или `TS` |
| `timestamptz` | `TSTZ` |
| `boolean` (только объявлением) | `Y`, `N`, `TRUE`, `FALSE`, `1`, `0` без учёта регистра |
| `string`, `text` | всё |

- Расширение (п. 4) идёт по цепочке стартового типа до первого типа, который вмещает **значения этого запуска**: каждый запуск хранит свой экземпляр dataset'а, а стартовый тип лишь держит схему между запусками. `decimal` расширяется и по масштабу: `decimal(38,2)` и значение `1.125` → `decimal(38,3)`. Запуск без ненулевых значений тип не меняет.
- **Хранимое значение:** `decimal` — каноническая форма (`.84` → `0.84`); `number` — кратчайшая запись double (§3.1), `inf`/`-inf`/`nan`; `date` из `TS` в полночь — первые 10 символов; `timestamp` — `YYYY-MM-DD HH:MM:SS[.ffffff]`; `timestamptz` — то же в UTC (смещение вычитается, с переходом через сутки); `boolean` — `true`/`false`; остальные — как пришли.
- Реализация: `src/catalog/result_types.cpp` — `OracleColumnInference` принимает значения по строкам и не держит результат в памяти.

**Форматы, которые отдаёт ofquack** (подтверждены в фазе 0, `PHASE0_REPORT.md` §4.2):
- числа меньше единицы — без ведущего нуля: `.84`, `-.5`;
- `DATE` — `YYYY-MM-DD`;
- `TIMESTAMP` — `YYYY-MM-DD HH:MM:SS.ffffff…`, 6–9 знаков дроби;
- `TIMESTAMP WITH TIME ZONE` — `YYYY-MM-DD HH:MM:SS.ffffff +HH:MM`;
- бесконечность `BINARY_DOUBLE` — `Inf`; колонка с ней выводится как `string`.

**Oracle `DATE` приходит без времени.** SQL-отчёт отдаёт колонку `DATE` в формате `YYYY-MM-DD`, и время суток теряется: `SYSDATE` → `2026-10-29`. Колонки `TIMESTAMP` время сохраняют; в Fusion это, например, `CREATION_DATE` и `LAST_UPDATE_DATE`. Модель данных отчёта не меняется (решение Р2, `DECISIONS.md`), поэтому это постоянное правило:
- автор, которому нужно время из колонки `DATE`, пишет `CAST(col AS TIMESTAMP)`;
- редактор SQL и Preview ДОЛЖНЫ показывать у колонок типа `date` из Oracle-запроса подсказку: "Oracle DATE columns come without the time of day. To keep the time, use CAST(column AS TIMESTAMP)";
- потеря времени тихая, и демон её не обнаруживает: по значению `2026-10-29` нельзя понять, было ли в исходной колонке время;
- правило «все `TS` с временем `00:00:00` → `date`» нужно для `CAST(col AS TIMESTAMP)` над колонкой, где времени на самом деле нет: такая колонка остаётся `date`.

## 4. Подстановка параметров в Oracle SQL

### 4.1 Токенизатор
Текст тела разбирается слева направо. Вне перечисленных ниже конструкций ищется `:имя`. Внутри — текст копируется без изменений.

| Конструкция | Начало | Конец |
|---|---|---|
| Строковый литерал | `'` (также с префиксом `N`/`n`) | `'`, не являющаяся частью `''` |
| q-литерал | `q'` / `Q'` / `nq'` / `Nq'` / `nQ'` / `NQ'` + символ-разделитель `X` | `X'`, где для `[ ( { <` закрывающий — `] ) } >` |
| Идентификатор в кавычках | `"` | `"`, не являющаяся частью `""` |
| Однострочный комментарий | `--` | конец строки |
| Многострочный комментарий | `/*` | `*/` (вложенность не поддерживается) |

- **Параметр:** `:` + `[A-Za-z][A-Za-z0-9_]*` — берётся максимально длинное имя. Сопоставление с `@param` — без учёта регистра.
- `:` + цифра — `E_PARAM_POSITIONAL`.
- `:` перед символом, не начинающим имя (например `::`, `: `), копируется как есть.
- Имена, начинающиеся с `__`, зарезервированы; в MVP встретить их в тексте — `E_PARAM_UNKNOWN`.
- Незакрытый литерал, идентификатор или комментарий — `E_SQL_TOKENIZE`.
- Найденный `:имя` без `@param` — `E_PARAM_UNKNOWN`. Объявленный, но не встретившийся параметр — предупреждение.
- После комментариев и пробелов тело ДОЛЖНО начинаться с `SELECT` или `WITH` (без учёта регистра), иначе `E_SQL_NOT_SELECT`.
- **Уточнения реализации** (`src/catalog/oracle_render.cpp`):
  - `::` копируется целиком: вторая `:` не начинает имя (R30: `:x::y`, `:bu::y` → `7::y`).
  - Префикс `q'` / `N'` распознаётся только в начале слова: `colq'…'` — это слово `colq` и обычная строка. Разделитель q-литерала не может быть пробельным символом; q-литерал закрывается только парой «разделитель + `'`».
  - «Сразу после `IN`» — предыдущая значимая лексема — слово `IN` целиком (не `JOIN`); `IN (:ids)` — уже не сразу после `IN`.
  - Сначала проверяется текст (`E_SQL_*`, `E_PARAM_POSITIONAL`, `E_PARAM_UNKNOWN`, `E_PARAM_LIST_CONTEXT`), потом значения. Ошибки текста содержат номер строки тела.
  - Нормализуются **все** объявленные параметры, а не только встретившиеся в тексте: из них строится `canonical_params` (§1.2). Поэтому объявленный, но неиспользуемый параметр без значения по умолчанию и без значения — `E_PARAM_MISSING`.
  - Имена во входных значениях сравниваются без учёта регистра; имя, которого нет в `@param`, — `E_PARAM_UNKNOWN`; одно имя дважды — тоже.
  - Элементы подзапроса списка — через `", "`, порции — через `" UNION ALL "`.

### 4.2 Литералы

| Тип | Подстановка |
|---|---|
| `integer`, `id` | каноническая форма; отрицательное — в скобках: `(-5)` |
| `number`, `decimal` | каноническая форма; отрицательное — в скобках: `(-12.5)` |
| `string`, `enum` | `'…'` с удвоением `'` |
| `date` | `DATE 'YYYY-MM-DD'` |
| `timestamp` | `TIMESTAMP 'YYYY-MM-DD HH:MM:SS[.ffffff]'` |
| `boolean` | `'Y'` / `'N'` |
| `list<T>` | только сразу после ключевого слова `IN` (между ними — только пробелы и комментарии), иначе `E_PARAM_LIST_CONTEXT`. Подстановка — подзапрос (ниже) |

`list<T>` → подзапрос по коллекциям Oracle, порциями не больше 999 элементов:
```
(SELECT column_value FROM TABLE(sys.<тип>(e1, …, e999))
 UNION ALL SELECT column_value FROM TABLE(sys.<тип>(e1000, …)))
```
| T | `<тип>` | элементы |
|---|---|---|
| `integer`, `id`, `number`, `decimal` | `odcinumberlist` | литералы чисел (отрицательные — в скобках) |
| `string` | `odcivarchar2list` | строковые литералы |
| `date`, `timestamp` | `odcidatelist` | `DATE '…'` / `TIMESTAMP '…'` |
| `boolean` | `odcivarchar2list` | `'Y'`/`'N'` |

Пустой список → `(SELECT NULL FROM dual WHERE 1 = 0)`.
Доступность `sys.odci*list` через SQL-отчёт BIP — **[Ф0]** ✅ (A2, `PHASE0_REPORT.md` §4.3). `odcidatelist` хранит Oracle `DATE`: у элемента `list<timestamp>` при сравнении теряется дробь секунды.

## 5. Получение данных

### 5.1 Вызов ofquack (Oracle-запрос)
Демон ДОЛЖЕН выполнять Oracle-запрос ровно так:
```sql
SELECT * FROM oracle_fusion_query(
    $rendered_sql,
    secret        := $connection_name,
    all_varchar   := true,
    on_cast_error := 'error',
    fetch_size    := $fetch_size        -- по умолчанию 10000; для Preview — 200
);
```
- `$rendered_sql` — тело после подстановки (§4), передаётся параметром подготовленного запроса DuckDB, не склейкой.
- Результат читается **потоково** (`PreparedStatement::Submit` и `QueryResultStream` DuckDB 2.0) по `DataChunk`, строки дописываются через `Appender` в таблицу-заготовку `ds."<stage>"` со всеми колонками `VARCHAR` (`c0`, `c1`, …; имена колонок отчёта запуск держит в памяти). Это даёт прогресс (строки), контроль `@max_rows` и отмену.
- Запуск держит три соединения: из ofquack читает одно — его прерывают отмена и тайм-аут (решение Р3); заготовку перечитывает второе; таблицы и `meta.*` пишет третье. Открытый результат принадлежит своему соединению, поэтому чтение и запись одно соединение не делят.
- Типы (§3.3) выводятся вторым проходом по заготовке, значения переносятся третьим, в порядке строк отчёта. Реализация — `src/run/run_engine.cpp`.
- При переносе из заготовки в таблицу экземпляра `''` заменяется на NULL (§3.3), затем значения приводятся к типам договора.
- `fetch_size` 10 000 — по замеру фазы 0: примерно на 7 % быстрее 5 000 при ~5 200 строк/с (`PHASE0_REPORT.md` §4.1). Каждый запрос к BI Publisher стоит 1–3,5 с накладных расходов, поэтому меньший размер страницы заметно замедляет загрузку.
- Имена колонок — как вернул отчёт (обычно в верхнем регистре). Сопоставление с `@column` — без учёта регистра.
- Ofquack сам добавляет `ORDER BY` для постраничного чтения. Автору для больших запросов рекомендуется свой `ORDER BY` по индексированному ключу (из документации ofquack); демон это не проверяет.

### 5.2 Пустой результат
Ofquack на запрос без строк бросает `IOException` с текстом, начинающимся с `Oracle Fusion returned no rows`. Демон ДОЛЖЕН:
1. Если все колонки объявлены `@column` **или** в `meta.query_schemas` есть схема для этого `definition_hash` — создать dataset с 0 строк и этой схемой. Запуск — `succeeded`, `rows = 0`.
2. Иначе — запуск `failed` с `E_EMPTY_UNKNOWN_SCHEMA` и подсказкой "The query returned 0 rows and its schema is unknown. Declare the columns with @column, or run the query with parameters that return rows".

Какая схема берётся: колонки из `meta.query_schemas` в их порядке, а у колонки, объявленной `@column` (имя без учёта регистра), — тип и заголовок из объявления. Схемы в `meta.query_schemas` ещё нет — колонки `@column` в порядке объявления. Пустой запуск `meta.query_schemas` не меняет.

Распознавание по тексту — временное, до доработки ofquack (§15).

### 5.3 Local-запрос
- Перед выполнением для каждой `@depends` находится экземпляр dataset'а (§6.3); если его нет или статус не `ready` — `E_DEPENDENCY_MISSING` (в `details` — список недостающих, для Smart Refresh).
- На соединении создаются временные представления: `CREATE TEMP VIEW <query_id> AS SELECT * FROM ds."<таблица экземпляра>"`, для импортов — `CREATE TEMP VIEW <name> AS SELECT * FROM xl_import."<name>"`. После выполнения они удаляются. Разрешение коротких имён во временные представления — **[Ф0]**.
- Тело проходит валидацию (§7), затем выполняется как подготовленный запрос с именованными параметрами `$имя`. Значения — по типам §3.1 (`list<T>` → `LIST`).
- Результат читается потоково через `Appender` в таблицу-заготовку `ds."stage__<run_id>"`, затем переносится в таблицу экземпляра с хранением по §3.2 (§3.4, `DECISIONS.md` Р9).

**Уточнения реализации** (`src/run/local_run.cpp`):
- **Зависимость-запрос** ищется по §10.2 (книга `workbook_id` запуска → проекты → примеры). Её параметры — аргументы `@depends`: `$имя` берёт каноническое значение параметра родителя, литерал — своё значение; по умолчанию — из её `@param`. Подключение Oracle-зависимости — `connection` запуска, иначе её `@connection`, иначе 422 `E_BAD_REQUEST`. Ключ экземпляра — по §1.3.
- **Что запускается** решает `deps` (§8.3) при старте родителя: `missing` — зависимости без `ready`-экземпляра, `all` — все, `none` — ни одна. Зависимости запускаются с тем же `deps`, той же книгой и `parent_run_id` родителя; повторный старт идущего экземпляра присоединяется к идущему запуску (§6.4). Родитель ждёт всех, затем выполняет свой SQL.
- **`E_DEPENDENCY_MISSING`** (409, до запуска): при `none` — запрос без `ready`-экземпляра; при любом `deps` — незарегистрированный запрос и отсутствующий импорт (их нельзя получить запуском). `details`:
  ```ts
  { missing: Array<{ kind: "query" | "import"; name: string;
                     query?: QueryRef; connection?: string; params?: Record<string, ParamValue>; instance_key?: string }> }
  ```
  Поля `query`…`instance_key` — у зарегистрированного запроса. Он же записывается в `meta.missing` книги (`requests` растёт с каждым отказом), если запуск передал `workbook_id`; без книги запись не делается. Успешный запуск экземпляра удаляет его записи из `meta.missing` (§8.3 `/v1/missing`).
- **`E_DEPENDENCY_FAILED`** (в `Run.error`): зависимость не стартовала (её отказ — в сообщении), завершилась ошибкой или отменой. Цикл зависимостей (`a → b → a`) обнаруживается, когда стартует зависимость, и даёт то же `E_DEPENDENCY_FAILED` у родителя с путём цикла.
- **Отмена и тайм-аут** родителя, ждущего зависимостей, отменяют зависимости, которые он сам запустил (не присоединённые).
- **Параметры** связываются типами: `integer` — `BIGINT` (больше 18 цифр — `HUGEINT`), `number` — `DOUBLE`, `decimal(p,s)` — `DECIMAL(p,s)`, `date`, `timestamp`, `boolean` — одноимённые, `string`, `id`, `enum` — `VARCHAR`, `list<T>` — `LIST` типа элемента.
- **Колонки** с одинаковыми без учёта регистра именами — `E_SQL_COMPILE` (у таблицы экземпляра не может быть двух таких колонок). Тип не из §3.4 хранится строкой и даёт предупреждение `W_TYPE_WIDENED`.
- `W_PARAM_UNUSED` — для параметра, которого нет ни в SQL, ни в аргументах `@depends` (так же в `POST /v1/queries/validate`).
- Ошибки выполнения — по §14.1 для Local; `@max_rows`, отмена и тайм-аут — как у Oracle-запуска (§5.4).

### 5.4 Пределы
- Лимит строк: `@max_rows`, иначе 1 000 000. Для Preview — 200.
- Демон читает до `limit + 1` строки. Если строка `limit + 1` получена — запуск помечается `truncated = true`, сохраняются первые `limit` строк, оставшееся чтение прерывается (`Connection::Interrupt()` на соединении запуска, затем поток результата закрывается).
- Тайм-аут запуска: 30 минут (`ofexcel_run_timeout`), по истечении — прерывание и `E_TIMEOUT`; запуск — `failed`.
- Отмена и тайм-аут прерывают соединение чтения повторно, раз в 100 мс, пока запуск не закончится: прерывание, пришедшее до начала запроса в DuckDB, при его начале сбрасывается. Пришедшие после чтения отмена и тайм-аут останавливают запуск между порциями заготовки и перед подменой версии. После подмены (§6.4) запуск уже `succeeded`.
- Ошибка чтения после отмены или тайм-аута считается отменой или тайм-аутом, каким бы исключением ни пришла. Что раньше, то и причина.

## 6. Хранилище

### 6.1 Имена таблиц
- Экземпляр dataset'а: `ds."<query_id>__<первые 12 символов instance_key>__v<N>"`, `N` — номер версии экземпляра (1, 2, …).
- Заготовка запуска (Oracle и Local): `ds."stage__<run_id без дефисов>"`; удаляется по завершении запуска в любом исходе.
- Импорт: `xl_import."<name>"`; его строки до коммита — `ds."stage__<import_id без дефисов>"` (§8.3).

### 6.2 DDL метаданных
Миграции применяются при старте по `meta.schema_version`. Для MVP — версия 1:

```sql
CREATE SCHEMA IF NOT EXISTS meta;
CREATE SCHEMA IF NOT EXISTS ds;
CREATE SCHEMA IF NOT EXISTS xl_import;

CREATE TABLE meta.schema_version (version INTEGER NOT NULL);

CREATE TABLE meta.state (
    key   VARCHAR PRIMARY KEY,        -- 'data_version', 'catalog_version'
    value VARCHAR NOT NULL
);

CREATE TABLE meta.connections (
    name        VARCHAR PRIMARY KEY,
    environment VARCHAR NOT NULL CHECK (environment IN ('DEV', 'TEST', 'PROD')),
    endpoint    VARCHAR NOT NULL,     -- https://host, без пути
    report_path VARCHAR NOT NULL,
    created_at  TIMESTAMP NOT NULL
);

CREATE TABLE meta.query_definitions (
    definition_hash VARCHAR NOT NULL,
    query_id        VARCHAR NOT NULL,
    version         INTEGER NOT NULL,
    engine          VARCHAR NOT NULL CHECK (engine IN ('oracle', 'local')),
    source_kind     VARCHAR NOT NULL CHECK (source_kind IN ('project', 'workbook', 'example')),
    source_ref      VARCHAR NOT NULL, -- имя проекта, workbook_id или 'builtin'
    header_json     VARCHAR NOT NULL, -- разобранный заголовок (§2), канонический JSON
    text            VARCHAR NOT NULL, -- исходный текст файла
    registered_at   TIMESTAMP NOT NULL,
    PRIMARY KEY (source_kind, source_ref, query_id, definition_hash)
);

CREATE TABLE meta.query_schemas (
    definition_hash VARCHAR NOT NULL,
    ordinal         INTEGER NOT NULL, -- с 0
    column_name     VARCHAR NOT NULL,
    contract_type   VARCHAR NOT NULL, -- 'id', 'integer', 'decimal(38,2)', …
    header          VARCHAR,          -- заголовок из @column или NULL
    PRIMARY KEY (definition_hash, ordinal)
);

CREATE TABLE meta.dataset_instances (
    instance_key    VARCHAR PRIMARY KEY,
    query_id        VARCHAR NOT NULL,
    definition_hash VARCHAR NOT NULL,
    connection_name VARCHAR NOT NULL, -- 'local' для Local-запросов
    params_json     VARCHAR NOT NULL, -- canonical_params
    current_table   VARCHAR,          -- NULL, пока нет успешной версии
    current_version INTEGER NOT NULL DEFAULT 0,
    prev_table      VARCHAR,
    data_version    BIGINT  NOT NULL DEFAULT 0,
    fetched_at      TIMESTAMP,
    row_count       BIGINT,
    truncated       BOOLEAN,
    status          VARCHAR NOT NULL CHECK (status IN ('empty', 'ready')),
    last_error_code VARCHAR,
    last_error      VARCHAR,
    last_access_at  TIMESTAMP NOT NULL
);

CREATE TABLE meta.runs (
    run_id          VARCHAR PRIMARY KEY,
    instance_key    VARCHAR NOT NULL,
    query_id        VARCHAR NOT NULL,
    definition_hash VARCHAR NOT NULL,
    connection_name VARCHAR NOT NULL,
    environment     VARCHAR,          -- NULL для local
    params_json     VARCHAR NOT NULL,
    workbook_id     VARCHAR,
    parent_run_id   VARCHAR,          -- для зависимостей
    user_name       VARCHAR,          -- пользователь Fusion; NULL для local
    status          VARCHAR NOT NULL CHECK (status IN ('queued', 'running', 'succeeded', 'failed', 'cancelled')),
    started_at      TIMESTAMP NOT NULL,
    finished_at     TIMESTAMP,
    rows_fetched    BIGINT NOT NULL DEFAULT 0,
    truncated       BOOLEAN NOT NULL DEFAULT false,
    result_table    VARCHAR,          -- версия, созданная этим запуском
    warnings_json   VARCHAR NOT NULL DEFAULT '[]',
    error_code      VARCHAR,
    error_message   VARCHAR
);

CREATE TABLE meta.trusted_definitions (
    definition_hash VARCHAR PRIMARY KEY,
    query_id        VARCHAR NOT NULL,
    origin          VARCHAR NOT NULL CHECK (origin IN ('local_editor', 'user_consent', 'example')),
    workbook_id     VARCHAR,
    trusted_at      TIMESTAMP NOT NULL
);

CREATE TABLE meta.missing (
    workbook_id     VARCHAR NOT NULL,
    instance_key    VARCHAR NOT NULL,
    query_id        VARCHAR NOT NULL,
    definition_hash VARCHAR NOT NULL,
    connection_name VARCHAR NOT NULL,
    params_json     VARCHAR NOT NULL,
    first_seen      TIMESTAMP NOT NULL,
    last_seen       TIMESTAMP NOT NULL,
    requests        BIGINT NOT NULL,
    PRIMARY KEY (workbook_id, instance_key)
);

CREATE TABLE meta.imports (
    name        VARCHAR PRIMARY KEY,
    workbook_id VARCHAR NOT NULL,
    source      VARCHAR NOT NULL,     -- 'Sheet1!tblBank' или 'Sheet1!A1:F200'
    schema_json VARCHAR NOT NULL,     -- [{"name":…,"type":…}]
    row_count   BIGINT NOT NULL,
    imported_at TIMESTAMP NOT NULL,
    data_version BIGINT NOT NULL
);

INSERT INTO meta.schema_version VALUES (1);
INSERT INTO meta.state VALUES ('data_version', '0'), ('catalog_version', '');
```

**Реестр запросов** (`src/meta/query_registry.cpp`):
- `header_json` — канонический JSON (§1) с ключами `id`, `engine`, `version`, `title`, `description`, `connection`, `max_rows` (пустые — `null`), `params: [{name, type, default, description}]` (`default` — строка, для `list<T>` — массив строк, нет — `null`), `columns: [{name, type, header}]`, `depends: [{kind: "query"|"import", name, arguments: [{name, kind: "param"|"string"|"number"|"date"|"boolean", value}]}]`.
- Источник заменяется целиком: перечитывание проектов — все строки `project`, сохранение из редактора — строки этого проекта, регистрация книги — строки этой книги. Удаление старых строк, вставка новых и новый `catalog_version` — в одной транзакции.
- **Одна версия — один текст.** В одном источнике (проект, книга, примеры) два разных текста с одинаковыми `@id` и `@version` — `E_QUERY_PARSE` для второго: в проекте второй файл по порядку имён не регистрируется, книга отклоняется целиком. Одинаковые тексты — одно определение.
- **`catalog_version`** — первые 16 шестнадцатеричных цифр SHA-256 от строк `source_kind \t source_ref \t query_id \t definition_hash \n` всех определений, отсортированных по байтам; пустой реестр — `""`. Те же файлы дают ту же версию и после перезапуска, поэтому кэш клиента не сбрасывается зря. Доверие (`meta.trusted_definitions`) в версию не входит.

### 6.3 Выбор экземпляра
Для запроса `Q` с определением `H`, подключением `C` и параметрами `P`: `instance_key` по §1.3. Если строки в `meta.dataset_instances` нет — создаётся со `status = 'empty'`.

Запуск создаёт строку экземпляра (или обновляет её `last_access_at`) и строку `meta.runs` со `status = 'running'` в одной транзакции, до чтения. Строк нет, если запрос отклонён раньше: не разбирается, не доверенный (`E_NOT_TRUSTED`), ошибка значения параметра (`E_PARAM_*`); для Oracle — нет подключения (`E_BAD_REQUEST`) или секрета с этим именем (`E_NOT_FOUND`), ошибка подстановки (`E_SQL_*`); для Local — нарушение §7 (`E_VALIDATION`, `E_SQL_COMPILE`), нет подключения для Oracle-зависимости (`E_BAD_REQUEST`), недостающая зависимость (`E_DEPENDENCY_MISSING`, §5.3).
- `environment` — из `meta.connections`; подключение только из `init.sql` без метки — `NULL`. У Local-запуска — `NULL`.
- `user_name` — `subject` из `fusion_scanner_sso_status()`; неизвестен — `NULL`. У Local-запуска — `NULL`.
- `warnings_json` — JSON-массив `Warning` (§8.2): `W_PARAM_UNUSED` (§4) с начала запуска, `W_TYPE_WIDENED` и `W_NUMBER_PRECISION` (§3.3) — к концу.

### 6.4 Подмена версии (успешный запуск)
В одной транзакции:
```sql
-- было: current_table = T_N, prev_table = T_{N-1}
DROP TABLE IF EXISTS ds."<T_{N-1}>";
UPDATE meta.dataset_instances
   SET prev_table = current_table, current_table = '<T_{N+1}>',
       current_version = current_version + 1, data_version = data_version + 1,
       fetched_at = now(), row_count = …, truncated = …, status = 'ready',
       last_error_code = NULL, last_error = NULL
 WHERE instance_key = …;
UPDATE meta.state SET value = CAST(CAST(value AS BIGINT) + 1 AS VARCHAR) WHERE key = 'data_version';
```
- Неудачный или отменённый запуск: удалить свою таблицу `T_{N+1}` (если создана), записать `last_error_code`/`last_error` в экземпляр, `current_table` не трогать.
- Одновременно для одного `instance_key` выполняется не больше одного запуска. Повторный `POST /v1/runs` для того же ключа возвращает уже идущий `run_id` (если не передан `force: true`; с `force` — `E_CONFLICT`, пока идущий не закончится).
- Экземпляры, у которых `last_access_at` старше 30 дней (`ofexcel_dataset_ttl_days`), удаляются вместе с таблицами при старте демона. Тогда же удаляются заготовки `ds."stage__*"`, оставшиеся от остановленного демона, а запуски со статусом `queued` или `running` становятся `failed` с `E_INTERNAL`.
- Номер новой версии — `current_version + 1` на момент создания таблицы; в той же транзакции `meta.runs` получает итог запуска, а успешный непустой запуск переписывает `meta.query_schemas` своей схемой (§3.3).
- Записи в `meta.*`, которые трогают общие строки (`data_version` в `meta.state`, строка экземпляра, схема определения), запуски делают по очереди: из двух транзакций DuckDB, обновивших одну строку, вторая отклоняется, а не ждёт. Реализация — `src/meta/datasets.cpp`.

## 7. Валидация Local SQL

Разбор — `duckdb::Parser`, обход AST. Нарушение любого правила — `E_VALIDATION` с номером правила и фрагментом.

| # | Правило |
|---|---|
| V1 | Ровно одна инструкция |
| V2 | Тип инструкции — `SELECT` (включая `WITH`, `UNION`, `EXCEPT`, `INTERSECT`, `VALUES` внутри `SELECT`) |
| V3 | Каждая ссылка на таблицу (`BaseTableRef`) без схемы — имя CTE этого запроса, имя `@depends`-запроса или имя `@depends`-импорта (без схемы) |
| V4 | Ссылка со схемой разрешена только `xl_import.<name>`, и только если `xl_import.<name>` объявлен в `@depends`. Указание каталога (`db.schema.table`) запрещено |
| V5 | Имя таблицы, похожее на путь или URL (содержит `.`, `/`, `\`, `:` или начинается с `'`), запрещено — защита от replacement scan (`FROM 'file.csv'`) |
| V6 | Табличные функции разрешены только: `unnest`, `range`, `generate_series` |
| V7 | Запрещены скалярные функции: `getenv`, `current_setting`, `ofexcel_*`, `fusion_scanner_*`, `oracle_fusion_*`, `read_text`, `read_blob` |
| V8 | Каждый `$имя` объявлен в `@param`; позиционные `?` и `$1` запрещены |
| V9 | Подзапросы и CTE проверяются по тем же правилам рекурсивно |

Векторы (запрос объявляет `@depends: ap_invoices(...)` и `@depends: xl_import.bank`, `@param bu: integer`):

| # | SQL | Результат |
|---|---|---|
| L1 | `SELECT * FROM ap_invoices` | OK |
| L2 | `SELECT * FROM ap_invoices i JOIN xl_import.bank b ON b.ref = i.invoice_num` | OK |
| L3 | `WITH t AS (SELECT * FROM ap_invoices) SELECT count(*) FROM t` | OK |
| L4 | `SELECT * FROM ap_invoices; SELECT 1` | V1 |
| L5 | `CREATE TABLE x AS SELECT 1` | V2 |
| L6 | `SELECT * FROM gl_balances` | V3 (не объявлено) |
| L7 | `SELECT * FROM xl_import.other` | V4 |
| L8 | `SELECT * FROM 'data.csv'` | V5 |
| L9 | `SELECT * FROM read_csv('x.csv')` | V6 |
| L10 | `SELECT * FROM oracle_fusion_query('SELECT 1 FROM dual')` | V6 |
| L11 | `SELECT getenv('HOME')` | V7 |
| L12 | `SELECT * FROM ap_invoices WHERE org_id = $bu` | OK |
| L13 | `SELECT * FROM ap_invoices WHERE org_id = $x` | V8 |
| L14 | `SELECT * FROM ap_invoices WHERE org_id = ?` | V8 |
| L15 | `SELECT * FROM range(10)` | OK |
| L16 | `SELECT * FROM (SELECT * FROM read_parquet('x'))` | V6 (через V9) |
| L17 | `SELECT * FROM memory.main.t` | V4 |

Валидатор — дополнительная защита, а не песочница (`SPEC.md` §8.4). Независимо от него демон работает с `enable_external_access = false`.

**Уточнения реализации** (`src/run/local_validator.cpp`):
- Разбор — встроенной грамматикой DuckDB (`Parser::GetBuiltinParser`), без расширений парсера. Текст, который не разбирается, — `E_SQL_COMPILE` без номера правила.
- Нарушение сообщается правилом, которое нарушено, даже внутри подзапроса или CTE (L16 — `V6`): V9 — это способ обхода, а не отдельный отказ. Сообщается первое найденное нарушение.
- V2 касается и источников в `FROM`: `SUMMARIZE`, `DESCRIBE`, `SHOW` и вложенные `INSERT … RETURNING` — тоже V2.
- V3: имена таблиц, CTE и `@depends` сравниваются без учёта регистра. CTE виден в своём `WITH` и ниже, но не снаружи подзапроса, где объявлен; CTE видит соседей по `WITH` и (в `WITH RECURSIVE`) себя.
- V6: табличная функция со схемой (`main.range`) — тоже V6.
- V7 проверяет имя функции без схемы и без учёта регистра: `OFEXCEL_VERSION()` — V7.
- V8: `$имя` сравнивается с `@param` без учёта регистра; `?` и `$1` — V8.
- Проверяются все выражения: список `SELECT`, `WHERE`, `GROUP BY`, `HAVING`, `QUALIFY`, `ORDER BY`/`LIMIT`, условия `JOIN`, `VALUES`, аргументы табличных функций, `PIVOT`.

## 8. HTTP API

### 8.1 Общее
- База: **HTTPS в обоих профилях** (решение Р6, `DECISIONS.md`): `https://localhost:<port>` или `https://127.0.0.1:<port>` с сертификатом от локального CA (`SPEC.md` §12.4). WebView Excel для Mac не делает запросов с HTTPS-страницы на HTTP, даже на loopback (`PHASE0_REPORT.md` §4.8). hosted — запросы с другого источника через CORS; local — тот же источник. Порт по умолчанию `47321`.
- **Сертификаты** лежат в `ofexcel_tls_dir` (по умолчанию `QEXCEL_HOME/tls`, каталог `0700`) и создаются командой `ofexceld install-cert [--dir DIR] [--no-trust]`:
  | Файл | Что это |
  |---|---|
  | `ca.crt` | Локальный CA: ECDSA P-256, 10 лет, CN `QExcel Local CA`, `basicConstraints` critical `CA:TRUE, pathlen:0`, `keyUsage` critical `keyCertSign, cRLSign`, `nameConstraints` critical `permitted DNS:localhost, IP:127.0.0.1/255.255.255.255` |
  | `ca.key` | Ключ CA, PEM PKCS#8 без пароля, права `0600` |
  | `server.crt` | Сертификат сервера: ECDSA P-256, 397 дней (не дольше срока CA), CN `localhost`, SAN `DNS:localhost, IP:127.0.0.1`, `extendedKeyUsage serverAuth`, `basicConstraints` critical `CA:FALSE` |
  | `server.key` | Ключ сервера, права `0600` |

  `install-cert` сохраняет уже созданный CA и перевыпускает только сертификат сервера, если нужно; без `--no-trust` добавляет CA в доверенные текущего пользователя (macOS — `login.keychain-db`, Windows — `CurrentUser\ROOT`). `ofexceld uninstall-cert [--dir DIR] [--no-trust]` убирает CA из доверенных и удаляет файлы. При запуске сервера сертификат сервера перевыпускается от того же CA, если до конца срока меньше 30 дней, если его нет или если он не подходит к ключу или к CA. Нет `ca.crt` — `ofexcel_start` отказывает с `E_UNSUPPORTED` и просит выполнить `ofexceld install-cert`.
- Тела запросов и ответов — `application/json; charset=utf-8`.
- **Проверки на каждом запросе** (до разбора тела):
  1. `Host` ∈ {`127.0.0.1:<port>`, `localhost:<port>`}, иначе 403 `E_HOST`.
  2. Для `/v1/*`: hosted — `Origin` **обязателен** и в точности равен `ofexcel_hosted_origin` (после нормализации: нижний регистр, `https://host[:port]`, без пути и завершающей `/`); local — `Origin` **может отсутствовать** (браузер не отправляет его на GET того же источника), но если есть — равен `https://localhost:<port>` или `https://127.0.0.1:<port>`. Иначе 403 `E_ORIGIN` **без** CORS-заголовков.
  3. local: заголовок `X-OF-Session` равен сессионному токену (сравнение за постоянное время), иначе 401 `E_SESSION`. В local именно токен, а не `Origin`, защищает запросы без `Origin`.
  4. Preflight `OPTIONS` проверяет `Host` и `Origin` (тот обязателен в обоих профилях), но не `X-OF-Session`: браузер не отправляет пользовательские заголовки в preflight.
  5. local: `GET /addin/*` — файлы надстройки — проверяет только `Host` (п. 1). Эти страницы и выдают токен, поэтому требовать его они не могут; чужой сайт не прочитает их без CORS-заголовков (их нет), а под чужим именем, указывающим на 127.0.0.1 (DNS rebinding), отказывает проверка `Host`. В hosted `/addin/*` не отдаётся (404).
- **Профиль local** (`src/server/routes_addin.cpp`):
  - Токен сессии — 32 байта `RAND_bytes`, 64 строчные hex-цифры, новый при каждом запуске сервера: страница, отданная прошлым запуском, к API уже не подходит.
  - `GET /addin/<путь>` отдаёт файлы из `ofexcel_addin_dir`, а если настройка пуста — встроенные (`taskpane.html` и `functions.json` из §10.1, пока надстройку не вшивает E1). В каждый HTML-файл (`.html`, `.htm`) сразу после открывающего `<head>` (или в начало, если его нет) вставляется `<meta name="qexcel-session" content="<токен>">`.
  - Путь с сегментом `.`, `..` или пустым, с `\`, `:` или NUL — 404, в том числе после раскодирования `%2e`/`%2f`. Файл должен лежать внутри `ofexcel_addin_dir` и после разрешения символьных ссылок.
  - Ответы `/addin/*` — с `Cache-Control: no-store` (токен меняется) и `X-Content-Type-Options: nosniff`.
- **CORS (hosted):** на `OPTIONS` для разрешённого `Origin` — `204` с заголовками:
  ```
  Access-Control-Allow-Origin: <ofexcel_hosted_origin>
  Access-Control-Allow-Methods: GET, POST, PUT, DELETE
  Access-Control-Allow-Headers: Content-Type, X-OF-Workbook, X-OF-Session
  Access-Control-Allow-Private-Network: true
  Access-Control-Max-Age: 600
  Vary: Origin
  ```
  На остальные ответы для разрешённого `Origin` — `Access-Control-Allow-Origin`, `Access-Control-Expose-Headers: X-OF-Data-Version, X-OF-Catalog-Version` (без него скрипт с другого источника эти заголовки не прочтёт) и `Vary: Origin`.
- **Каждый ответ** `/v1/*` содержит заголовки `X-OF-Data-Version` и `X-OF-Catalog-Version`.
- **Ошибка:** HTTP-статус из §14 и тело
  ```ts
  type ErrorBody = { error: { code: string; message: string; details?: unknown } };
  ```
  `message` — на английском, для показа пользователю (решение Р7).

### 8.3 Маршруты

**`GET /v1/health`** → 200
```ts
{ product: "qexcel"; version: string; api: { version: "1.0"; min_client: "1.0" };
  profile: "hosted" | "local"; data_version: number; catalog_version: string; time: string }
```

**`GET /v1/status`** → 200
```ts
{ connections: Array<{ name: string; environment: Environment; host: string;
                       signed_in: boolean; user?: string; expires_in?: number }>;
  active_runs: number; warnings: Warning[] }
```
Подключения — строки `meta.connections` по имени; `host` — `host[:port]` из `endpoint`; `signed_in`, `user` и `expires_in` — из `fusion_scanner_sso_status()` (токен не выдаётся никогда). `user` нет, если ofquack не знает субъекта. `expires_in` — секунд до истечения токена, только при `signed_in`: панель предупреждает за 15 минут (`DECISIONS.md` Р5).

**`GET /v1/connections`** → `{ connections: Array<{ name; environment; endpoint; report_path }> }` — строки `meta.connections` по имени, без учётных данных и токенов.

**`POST /v1/connections`** `{ name; environment; endpoint; report_path }` → 201 с тем же объектом после нормализации. Создаёт строку `meta.connections` и секрет `CREATE SECRET <name> (TYPE oracle_fusion, PROVIDER browser, ENDPOINT …, REPORT_PATH …, SSO_TIMEOUT_SECONDS 300)` в памяти (не `PERSISTENT`) — в одной транзакции: либо оба, либо ничего. Имя занято строкой или любым секретом (имена секретов общие для всех типов) — 409 `E_CONFLICT`. При старте демона секреты пересоздаются из `meta.connections`; подключения из `init.sql` имеют приоритет при совпадении имён.
- Тело не объект JSON — 400 `E_BAD_REQUEST`; поле отсутствует или не строка — 422 `E_BAD_REQUEST`.
- `name` — по §1; `environment` — ровно `DEV`, `TEST` или `PROD`; `endpoint` — `https://host[:port]` по правилам `ofexcel_hosted_origin` (§8.1.1: нижний регистр, без пути, завершающей `/` и `user@`), путь к сервису ofquack добавляет сам; `report_path` — абсолютный путь (`/…`), до 1024 байт, без управляющих символов. Иначе 422 `E_BAD_REQUEST`.

**`POST /v1/connections/{name}/test`** → `{ ok: boolean; user?: string; error?: {code; message} }` — выполняет `SELECT 1 FROM dual` через §5.1. Неудача — это ответ, а не ошибка: 200 с `ok: false` и кодом по §14.1 (нет входа — `E_FUSION_AUTH`). Нет секрета `oracle_fusion` с таким именем — 404 `E_NOT_FOUND`.

**`POST /v1/auth/login`** `{ connection: string }` → 200 `{ user: string }`. Вызывает `fusion_scanner_sso_login()` для секрета подключения; ответ — после завершения входа или по тайм-ауту 300 с. Любая неудача входа (тайм-аут, закрытое окно, не найден браузер) — 409 `E_FUSION_AUTH`. Клиент ДОЛЖЕН ждать ответа не меньше 310 с. Одновременно — не больше одного входа на подключение: второй запрос ждёт первый и получает его токен без нового окна (ofquack сверх того допускает один вход на процесс). Ещё действующий токен ofquack возвращает без браузера; `user` — `""`, если субъект неизвестен.

**`POST /v1/auth/logout`** `{ connection }` → 204. Забывает токен ofquack для хоста подключения; профиль браузера не трогает. Неизвестное подключение у `login` и `logout` — 404 `E_NOT_FOUND`.

**`GET /v1/dictionary/tables?connection=&q=&limit=50`** → `{ tables: Array<{ name: string; description?: string }> }` — через `oracle_fusion_tables()`, фильтр по подстроке имени без учёта регистра.

**`GET /v1/dictionary/columns?connection=&table=`** → `{ columns: Array<{ name; type?; description? }> }` — через `oracle_fusion_columns(table)`.

**Уточнения реализации словаря** (`src/server/routes_dictionary.cpp`):
- `connection` обязателен (иначе 422 `E_BAD_REQUEST`) и должен быть секретом `oracle_fusion` (иначе 404 `E_NOT_FOUND`). Ошибки ofquack — по §14.1 (нет входа — 409 `E_FUSION_AUTH`).
- `tables`: `q` пусто — все; имена, которые начинаются с `q`, идут первыми, затем по имени без учёта регистра. `limit` — от 1 до 1000, по умолчанию 50, иначе 422 `E_BAD_REQUEST`. `description` — описание из словаря Fusion, если оно не пустое.
- `columns`: `table` обязателен (422), имя без учёта регистра; таблицы нет в словаре — 404 `E_NOT_FOUND`. Колонки — в порядке таблицы; `type` — тип Oracle, у `NUMBER` с точностью — `NUMBER(p,s)`; колонки представления — из `all_tab_columns`, без описания.
- Список таблиц и колонки ofquack кэширует сам (`~/.fusion_scanner/metadata.duckdb`, срок — его по умолчанию): повторный запрос не стоит вызова BI Publisher.

**`GET /v1/queries?workbook=<id>`** → `{ queries: QuerySummary[] }` — проекты, примеры и (если передан `workbook`) запросы этой книги. Все определения, а не только выбранные по §10.2; порядок — книга, проекты, примеры, внутри — по `id`, затем новые версии первыми.

`QuerySummary` строится из текста определения: `params` и `columns` — из `@param` и `@column`; без `@column` — из `meta.query_schemas` этого хеша, если она есть. `ParamDef.default` для `list<T>` — элементы через `", "`. `ColumnInfo.header` — заголовок из `@column`, иначе имя колонки.

**`GET /v1/queries/{id}?source_kind=&source_ref=&workbook=`** → `QuerySummary & { text: string }`. Без `source_kind` — определение, которое выбирает §10.2 (запросы книги `workbook` первыми, если она передана); с `source_kind` (и `source_ref`, если передан) — наибольшая версия в этом источнике. Нет — 404 `E_NOT_FOUND`; `source_kind` не `project`/`workbook`/`example` — 422 `E_BAD_REQUEST`.

**`PUT /v1/queries/{id}`** `{ project: string; text: string }` → 200 `QuerySummary`. Пишет файл `<каталог проектов>/<project>/queries/<id>.sql` (через временный файл и переименование; каталоги создаются), заново читает этот проект и регистрирует определение, а хеш добавляет в `meta.trusted_definitions` с `origin = 'local_editor'` (если хеша там ещё нет): тот же текст в книге тоже доверенный. `@id` в тексте ≠ `{id}` или заголовок не разбирается — 422 `E_QUERY_PARSE`, в `details.errors` — ошибки разбора `{code, message, line?}`; файл не пишется. Другой файл проекта с тем же `@id` и `@version`, но другим текстом — 422 `E_QUERY_PARSE`, файл не пишется. `{id}` не по §1 или имя проекта не по §1 «Пути на диске» — 422 `E_BAD_REQUEST`.

**`PUT /v1/workbooks/{workbook_id}/queries`** `{ queries: Array<{ text: string }> }` → `{ queries: QuerySummary[] }` в порядке запроса. Заменяет набор запросов книги в `meta.query_definitions` (`source_kind = 'workbook'`); пустой массив удаляет все. Хеши книги не доверяются автоматически.
- **Доверие** (`trusted` в `QuerySummary` и проверка перед запуском) — свойство хеша: он есть в `meta.trusted_definitions` **или** тот же текст зарегистрирован в проекте или среди примеров. Запросы проектов и встроенные примеры доверенные по источнику (`DECISIONS.md` Р8); при регистрации примеры записываются в `meta.trusted_definitions` с `origin = 'example'`. Подтверждать нужно только тексты книги, которых нет ни в проекте, ни среди примеров (§9.3).
- Всё или ничего: если хоть один текст не разбирается — 422 `E_QUERY_PARSE`, набор книги не меняется, `details: { queries: Array<{ index: number; errors: Array<{ code; message; line? }> }> }` (`index` — с 0).
- `workbook_id` — UUID v4 в нижнем регистре (§9.1), иначе 422 `E_BAD_REQUEST`.

**`POST /v1/queries/validate`** `{ text: string }` → 200
```ts
{ ok: boolean; header?: QuerySummary; params_in_text: string[];
  errors: Array<{ code: string; message: string; line?: number }>; warnings: Warning[] }
```
- Сначала заголовок (§2): его ошибки — с `line` (0 не пишется). Если он разобран, то тело: для `oracle` — проверки текста токенизатора (§4.1, без значений), для `local` — валидатор (§7); их ошибки — без `line`, номер строки тела — в `message`. `ok` — нет ни одной ошибки.
- `header` — только если заголовок разобран. `source` и `trusted` — как у зарегистрированного определения с этим хешем (первого в порядке `GET /v1/queries`); незарегистрированный текст — `{ kind: "workbook", ref: "" }`, `trusted: false`.
- `params_in_text` — `:имя` (oracle) или `$имя` (local) в нижнем регистре, по одному разу, в порядке появления; при ошибке тела — найденные до неё.
- `warnings` — `{ code: "W_PARAM_UNUSED" }` для каждого объявленного, но не использованного параметра. Параметр local-запроса, переданный в аргумент `@depends` (`$имя`), использован.

**`POST /v1/preview`**
```ts
{ text?: string; query?: QueryRef; connection?: string;
  params: Record<string, ParamValue>; limit?: number /* ≤ 200 */ }
```
→ 200 `{ columns: ColumnInfo[]; rows: unknown[][]; elapsed_ms: number; truncated: boolean;
          rendered_sql?: string /* только oracle */; warnings: Warning[] }`.
- Ровно одно из `text` / `query`. Текст из `text` — это работа автора: не требует доверия, но проходит разбор (§2) и, для local, валидацию (§7).
- `query` из книги без доверия — 403 `E_NOT_TRUSTED`.
- Preview не создаёт экземпляр dataset'а и не пишет в `meta.runs`. Типы — по §3.3 на строках Preview (без записи в `meta.query_schemas`).

**Уточнения реализации** (`src/run/preview.cpp`, маршрут — `src/server/routes_runs.cpp`):
- `query` ищется по хешу среди всех зарегистрированных определений, в том числе любой книги: у хеша один текст, и доверие — его свойство. `id` должен совпасть без учёта регистра, иначе 404 `E_NOT_FOUND`.
- `limit` — целое от 1 до 200, по умолчанию 200; иначе 422 `E_BAD_REQUEST`. Ни `text`, ни `query`, или оба — 422 `E_BAD_REQUEST`. `params` и `connection` — как у `POST /v1/runs`.
- Читается до `limit + 1` строки, как в §5.4; страница ofquack — 200 строк (§5.1), так что при `limit = 200` и больших данных это вторая страница. `truncated` — строка `limit + 1` была. `elapsed_ms` — весь вызов.
- Oracle: стартовый тип колонки — из `meta.query_schemas` этого хеша (§3.3 п. 2), схема только читается. Пустой результат — не ошибка: колонки по §5.2 (схема и `@column`), а если схема неизвестна — `columns: []`.
- Local: зависимости не запускаются, читаются их текущие версии; зависимость без данных — 409 `E_DEPENDENCY_MISSING` с `details` по §5.3, но без записи в `meta.missing`. Значения хранятся и кодируются так же, как при запуске (§3.4, Р9).
- Ошибки — по §14.1 со статусами из §14; `E_TYPE_DECLARED_MISMATCH` — 422. Preview прерывается по `ofexcel_run_timeout`: 504 `E_TIMEOUT`.

→ 202 `Run`.
- Определение ищется по `QueryRef`: тот же `hash` и `id` (без учёта регистра) среди запросов книги `workbook_id` (если передана), проектов и примеров — в этом порядке. Нет — 404 `E_NOT_FOUND`.
- Недоверенное определение — 403 `E_NOT_TRUSTED`; ни запуск, ни экземпляр не создаются. Остальные отказы до запуска — §6.3.
- Повторный запуск идущего экземпляра — 202 с идущим `Run` (§6.4).
- `params` — объект; числа JSON читаются своим текстом (§3.1). `deps` — `missing`, `all` или `none`, `force` — boolean; иначе 422 `E_BAD_REQUEST`. Значение-объект у параметра — 422 `E_PARAM_TYPE`.
- Для local: зависимости запускаются раньше (`deps = all` — все; `missing` — только без `ready`-экземпляра; `none` — не запускаются, а отсутствие даёт `E_DEPENDENCY_MISSING`). Запуски зависимостей получают `parent_run_id`. Ошибка любой зависимости — родительский запуск `failed` с `E_DEPENDENCY_FAILED`. Подробности — §5.3. `connection` у Local-запроса — подключение его Oracle-зависимостей; сам запуск идёт с `connection = "local"`.
- `connection` для oracle: из тела, иначе из `@connection`, иначе 422 `E_BAD_REQUEST`.

**`GET /v1/runs/{run_id}`** → `Run`. Нет запуска — 404 `E_NOT_FOUND` (так же у `/cancel` и `/rows`).

`Run` строится из `meta.runs`: `params` — `canonical_params` (§1.2: строки, для `list<T>` — массивы строк); время — `YYYY-MM-DDTHH:MM:SSZ`; `rows_fetched` идущего запуска — сколько строк прочитано на этот момент; `depends_on` — запуски с этим `parent_run_id`, старые первыми (у Oracle-запуска пуст; запуск зависимости, к которому Local-запуск присоединился, в нём не числится — он начат другим); `error` — `{code, message}`, если запуск завершился ошибкой или отменой.

**`POST /v1/runs/{run_id}/cancel`** → `Run`. Для завершённого запуска — без изменений. Отмена ДОЛЖНА переводить запуск в `cancelled` не позже чем через 5 с **[Ф0]**. Маршрут ждёт окончания запуска до 5 с и отвечает уже его итогом.

**`GET /v1/runs/{run_id}/rows?offset=0&limit=5000`** → `RowsPage`. Только для `succeeded`, иначе 409 `E_RUN_NOT_FINISHED`. `limit` — от 1 до 20 000, `offset` ≥ 0, иначе 422 `E_BAD_REQUEST`. Читает `result_table` запуска; если она уже удалена (новая версия вытеснила её из `prev_table`, §6.4, или экземпляр удалён) — 410 `E_GONE`. Предыдущая версия, пока она в `prev_table`, читается.

`RowsPage`: строки — в порядке, в котором запуск их сохранил; `total` — число строк таблицы; `truncated` — у запуска (у экземпляра — для `/v1/datasets/…/rows`). Тип колонки — из `meta.query_schemas` этого хеша, если там колонка с тем же именем хранится так же; иначе — по типу хранения (`BIGINT` → `integer`, `DECIMAL(p,s)` → `decimal(p,s)`, `DOUBLE` → `number`, `DATE`, `TIMESTAMP`, `BOOLEAN` — одноимённые, остальное — `string`): схема в `meta.query_schemas` — последнего запуска, а старая версия могла иметь более узкий тип (§3.3 п. 4). `header` — из `@column`, иначе имя. Значения — по §3.2 (`EncodeJsonValue`). Чтение строк обновляет `last_access_at` экземпляра.

**`GET /v1/runs?query=<id>&workbook=<id>&limit=50`** → `{ runs: Run[] }`, новые первыми. `query` — без учёта регистра; `limit` — от 1 до 1000, иначе 422 `E_BAD_REQUEST`.

**`GET /v1/datasets`** → `{ datasets: Array<{ instance_key; query: QueryRef; connection; params; status; fetched_at?; row_count?; truncated?; last_error? }> }` — по `query_id`, затем `instance_key`; `last_error` — `{code, message}`.

**`GET /v1/datasets/{instance_key}/rows?offset=&limit=`** → `RowsPage` по `current_table`; `status = 'empty'` — 409 `E_DEPENDENCY_MISSING`; нет экземпляра — 404 `E_NOT_FOUND`.

**`DELETE /v1/datasets/{instance_key}`** → 204. Удаляет таблицы `current_table` и `prev_table` и строку экземпляра, увеличивает `data_version`. Запуски остаются в истории, их строки — 410 `E_GONE`. Экземпляр обновляется — 409 `E_CONFLICT`; нет экземпляра — 404 `E_NOT_FOUND`. Реализация маршрутов — `src/server/routes_runs.cpp`.

**`POST /v1/imports`** `{ name: string; workbook_id: string; source: string; columns: Array<{ name: string; type: string }> }` → 201 `{ import_id: string }`. Типы колонок — из §3.2, кроме `timestamptz`.
**`POST /v1/imports/{import_id}/rows`** `{ rows: unknown[][] }` → 204. Значения — в кодировке §3.2 (даты — строками).
**`POST /v1/imports/{import_id}/commit`** → 200 `{ name; rows: number }`. Атомарно заменяет `xl_import."<name>"`, увеличивает `data_version`. Незакоммиченный импорт удаляется через 10 минут.

**Уточнения реализации** (`src/meta/imports.cpp`, маршруты — `src/server/routes_imports.cpp`):
- `name` — идентификатор по §1 (§12 п. 2 даёт именно такое); `workbook_id` — UUID v4 (§9.1); `source` — непустая строка до 1024 байт без управляющих символов; `columns` — от 1 до 16 384, имена — непустые, до 255 байт, без управляющих символов, разные без учёта регистра. Иначе 422 `E_BAD_REQUEST`.
- Строки ждут коммита в `ds."stage__<import_id без дефисов>"` (§6.1) — её, как и заготовку запуска, удаляет очистка при старте (§6.4). Всего в импорте — не больше 1 048 576 строк.
- **Ячейка**: `null` и `""` — пустая ячейка, хранится NULL (Excel их не различает, §10.2). `string`, `text` принимают строку, число (своим текстом) и boolean (`true`/`false`). `id` — строку или число из цифр со знаком, хранится как написано, с ведущими нулями (ради них колонка и `id`, §12 п. 3). Остальные типы читаются по правилам ввода §3.1 (`integer`, `number`, `decimal(p,s)`, `date`, `timestamp`, `boolean`); `integer` длиннее 18 цифр не помещается в `BIGINT` — отказ с советом взять `id` или `number`.
- **Порция — всё или ничего**: ячейка не по типу или строка другой ширины — 422 `E_BAD_REQUEST` с номером строки в импорте (с 1) и именем колонки, ни одна строка порции не сохраняется. Объект вместо ячейки — тоже 422, с номером строки в порции.
- **Коммит** — в одной транзакции: старая таблица удаляется, новая создаётся из заготовки в порядке строк, строка `meta.imports` заменяется (`schema_json` — канонический JSON `[{name, type}]`, `data_version` — новое значение `meta.state`). Читатели видят старую таблицу или новую. Имя общее для всех книг: импорт другой книги с тем же именем заменяет таблицу.
- **Срок**: импорт, у которого 10 минут не было ни порции, ни коммита, удаляется вместе с заготовкой при следующем обращении к `/v1/imports*`. Неизвестный, закоммиченный или удалённый `import_id` — 404 `E_NOT_FOUND`.

**`POST /v1/trust`** `{ workbook_id: string; hashes: string[] }` → `{ trusted: string[] }`. Пишет `origin = 'user_consent'` и `workbook_id`. Хеш, которого нет среди запросов книги, — 422 `E_BAD_REQUEST`.
- Всё или ничего: при отказе не доверяется ни один хеш.
- В ответе — хеши запроса, каждый один раз, в его порядке. Хеш, уже доверенный, сохраняет прежний `origin`.
- `workbook_id` — UUID v4 (§9.1), `hashes` — массив строк; иначе 422 `E_BAD_REQUEST`.

**`POST /v1/batch`** — §10.3.

**`GET /v1/catalog`** → `{ catalog_version: string; functions: Array<{ id; name; description; params: ParamDef[] }> }`. В MVP — 4 функции ядра (§10.1): `params` — `name` и `type` из `parameters` `functions.json`. Тот же `functions.json` отдаёт `/addin/functions.json` (`src/batch/formulas.cpp`).

**`GET /v1/missing?workbook=<id>`** → `{ missing: Array<{ query: QueryRef; connection: string; params: Record<string, ParamValue>; first_seen; last_seen; requests }> }`. Записи старше 7 дней удаляются; запись удаляется после успешного запуска этого `instance_key`. `workbook` — UUID v4, иначе 422 `E_BAD_REQUEST`. «Старше» — по `last_seen`; удаляются при чтении списка, у всех книг. Порядок — по `query_id`, затем `instance_key`.

**`GET /addin/*`** (только local) — вшитые файлы; `functions.json` — по §10.1.

## 9. Книга Excel

### 9.1 Идентификатор книги
`Office.context.document.settings` ключ `qexcel.workbook_id` — UUID v4. Создаётся при первом сохранении запроса или привязки в книге (`settings.saveAsync`).

### 9.2 Хранение в книге
Один `CustomXmlPart` в пространстве имён `urn:qexcel:workbook:v1`:
```xml
<qexcel xmlns="urn:qexcel:workbook:v1" schema="1"><payload><![CDATA[ … JSON … ]]></payload></qexcel>
```
- JSON внутри CDATA: последовательность `]]>` ДОЛЖНА записываться как `]]\u003e` (она может встретиться только внутри JSON-строк, где это то же самое, поэтому это корректно).
- При сохранении старая часть удаляется и создаётся новая — через API Excel (`workbook.customXmlParts.getByNamespace` → `delete` → `add`, ExcelApi 1.5) в одном `sync`. Общий `Office.context.document.customXmlParts` — API Word, в Excel для Mac его нет.
- **Секретов, токенов и паролей в книге нет.**
- **Сохранение из редактора** (`addin/src/editor/model.ts`, TASKS.md D3; чтение при открытии книги и диалог доверия — D5): у книги без `workbook_id` он создаётся (§9.1); запрос заменяет в `queries` запрос с тем же `id` (без учёта регистра; в книге один текст на запрос); все тексты книги регистрируются `PUT /v1/workbooks/{id}/queries`, `hash` берётся из ответа; сохранённый текст — работа автора на этой машине, поэтому он сразу подтверждается `POST /v1/trust`; часть книги пишется последней, так что текст, который демон отверг, в книгу не попадает. `bindings` и `imports` сохраняются как были.

```ts
type WorkbookPayload = {
  schema: 1;
  workbook_id: string;
  queries: Array<{ id: string; hash: string; text: string;
                   saved_by?: string /* пользователь Fusion */; saved_at: string }>;
  bindings: Binding[];
  imports: Array<{ name: string; sheet: string; table?: string; range?: string;
                   reimport_before_run: boolean;
                   columns: Array<{ name: string; type: string }> }>;
};

type Binding = {
  binding_id: string;                      // UUID v4
  target: { kind: "table"; sheet: string; table: string };
  query: QueryRef;                         // hash ДОЛЖЕН быть среди queries[] книги или в проекте
  connection?: { name: string; host: string };   // для oracle
  params: Record<string, { ref: string } | { value: ParamValue }>;  // ref — "Лист!B2" или имя
  schema_policy: "strict" | "append";
  query_columns: number;                   // сколько первых колонок таблицы принадлежат запросу
  last_success?: { at: string; rows: number; truncated: boolean; run_id: string };
  partial?: { at: string; run_id: string }; // запись прервалась (§11.3)
};
```

### 9.3 Открытие книги и доверие
1. Прочитать `WorkbookPayload`. Если части нет — книга без запросов.
2. `PUT /v1/workbooks/{workbook_id}/queries` с текстами.
3. Если есть `trusted: false` — показать диалог подтверждения до любых других действий с этими запросами. Диалог ДОЛЖЕН показать для каждого запроса: `id`, `title`, `saved_by`, `saved_at`, подключение и окружение из привязок, **полный текст SQL**, список таблиц (лексемы после `FROM`/`JOIN` вне литералов и комментариев — для показа, не для безопасности) и предупреждение:
   > Запрос выполнится под вашей учётной записью Fusion. Если вы сохраните и отправите книгу, полученные данные уйдут вместе с ней.
4. "Trust" → `POST /v1/trust`. "Don't trust" → запросы и привязки показываются с пометкой "not trusted", запуск недоступен, формулы по ним возвращают `#N/A` "Query not trusted".
5. Если `connection.host` привязки не совпадает с хостом подключения с тем же именем у пользователя — предупреждение с обоими хостами; запуск — только после явного выбора подключения пользователем.

## 10. Формулы

### 10.1 `functions.json` ядра
```json
{
  "functions": [
    { "id": "TABLE", "name": "TABLE",
      "description": "Результат запроса QExcel как массив; первая строка — заголовки",
      "parameters": [
        { "name": "query", "type": "string", "dimensionality": "scalar" },
        { "name": "args", "type": "any", "dimensionality": "matrix", "repeating": true, "optional": true } ],
      "result": { "type": "any", "dimensionality": "matrix" } },
    { "id": "CALL", "name": "CALL",
      "description": "Скалярное значение запроса QExcel (результат 1 × 1)",
      "parameters": [
        { "name": "query", "type": "string", "dimensionality": "scalar" },
        { "name": "args", "type": "any", "dimensionality": "matrix", "repeating": true, "optional": true } ],
      "result": { "type": "any", "dimensionality": "scalar" } },
    { "id": "ASOF", "name": "ASOF",
      "description": "Время последнего успешного получения данных запроса",
      "parameters": [
        { "name": "query", "type": "string", "dimensionality": "scalar", "optional": true },
        { "name": "args", "type": "any", "dimensionality": "matrix", "repeating": true, "optional": true } ],
      "result": { "type": "number", "dimensionality": "scalar" } },
    { "id": "STATUS", "name": "STATUS",
      "description": "Состояние QExcel: OK, NOT_SIGNED_IN, STALE, OFFLINE",
      "parameters": [],
      "result": { "type": "string", "dimensionality": "scalar" } }
  ]
}
```

### 10.2 Семантика
- **Разрешение запроса по имени** `query`: запросы книги (по `workbook_id`) → проекты → примеры; внутри источника — по `@id` без учёта регистра. Если в одном источнике несколько определений с одним `@id` — берётся с наибольшим `@version`. Источник здесь — уровень: книга, все проекты вместе, примеры. Равные версии в разных проектах — первый проект по байтам имени (в одном проекте одна версия — один текст, §6.2). Не найдено — `#NAME?` (`invalidName`). Реализация — `FindQuery` в `src/meta/query_registry.cpp`.
- **Аргументы** — позиционно в порядке `@param`. Аргумент-матрица для скалярного типа ДОЛЖЕН быть 1 × 1, иначе `#VALUE!`. Для `list<T>` — матрица разворачивается по строкам, пустые ячейки пропускаются. Пустая ячейка или пропущенный аргумент → значение по умолчанию или `E_PARAM_MISSING` (`#VALUE!`). Excel передаёт пустую ячейку и пропущенный аргумент как `null`, а `""` и ячейку с формулой `=""` — как `""` (`PHASE0_REPORT.md` §4.8); обе формы трактуются как пусто.
- **Даты в аргументах.** Excel передаёт дату из ячейки как серийное число (`DATE(2026,1,1)` → 46023). Для параметров типа `date` и `timestamp` число ДОЛЖНО трактоваться как серийная дата Excel с учётом системы дат книги (1900 или 1904) и превращаться в `YYYY-MM-DD` / `YYYY-MM-DD HH:MM:SS` до отправки в демон (§3.1). Строка — как ISO-дата.
- **Подключение** для oracle-запроса в формуле: подключение по умолчанию книги (`settings` ключ `qexcel.default_connection`), иначе `@connection`, иначе `#N/A` "No connection selected".
- **`OF.TABLE`** читает `current_table` экземпляра (§6.3); **никогда** не запускает запрос. Нет данных — `#N/A` и запись в `meta.missing`. Строк больше 10 000 (`ofexcel_spill_max_rows`) — `#N/A` "Result too large: load it into a table". Результат: первая строка — заголовки (`header`), далее значения по §3.2 для Excel (даты — серийные числа, `decimal` — числа, `id` — строки).
- **`OF.CALL`** — то же, но результат ДОЛЖЕН быть ровно 1 строка × 1 колонка, иначе `#VALUE!` "Expected a 1 × 1 result, got R × C". `NULL` → `#N/A`.
- **`OF.ASOF(query, args…)`** — `fetched_at` экземпляра в локальном времени машины как серийное число Excel; нет данных — `#N/A`. **`OF.ASOF()`** без аргументов — минимум `last_success.at` по всем привязкам книги; вычисляется в shared runtime без обращения к демону.
- **`OF.STATUS()`** — `OFFLINE` (демон недоступен), `NOT_SIGNED_IN` (подключение по умолчанию без входа), `STALE` (у какой-либо привязки книги последняя попытка обновления неудачна), иначе `OK`.
- **Local-запрос в формуле** выполняется локально, если его экземпляра нет, но все зависимости `ready` (без сети). Если зависимости не готовы — `#N/A` и запись в `meta.missing` по каждой недостающей.

### 10.3 `/v1/batch`
```ts
// запрос
{ calls: Array<{ i: number; kind: "table" | "call" | "asof"; query: string; args: unknown[][][] }>;
  connection?: string;          // подключение книги по умолчанию (DECISIONS.md Р11)
  date_system?: 1900 | 1904 }   // система дат книги, по умолчанию 1900
// заголовок X-OF-Workbook: <workbook_id>

// ответ
{ data_version: number; catalog_version: string;
  results: Array<{ i: number; v?: unknown /* scalar или unknown[][] */;
                   e?: { code: "invalidValue" | "invalidName" | "notAvailable"; msg: string } }> }
```
- `args` — массив аргументов, каждый — матрица (как передаёт Excel).
- Порядок обработки вызова: разрешение запроса → проверка доверия → нормализация аргументов (§3.1) → `instance_key` → чтение или локальное выполнение.
- **Кэш результата** (сервер и клиент) по ключу `(kind, query_id, definition_hash, connection_name, canonical_params, data_version экземпляра и всех его зависимостей, user_name)`. Клиент сбрасывает кэш целиком при смене `data_version` или `catalog_version` в ответе или в `/v1/health` (опрос каждые 30 с и при возврате фокуса).
- **Деление при ошибках** применяется только к локальному выполнению, при `E_SQL_DATA` (§14). Бюджет — не больше 2 × число групп дополнительных выполнений и не больше 2 с на пакет. В MVP — по `DECISIONS.md` Р10: группа (вызовы одного Local-запроса) готовится один раз и выполняется для каждого набора аргументов, поэтому делить нечего; `E_SQL_DATA` — ошибка только своих ячеек, любая другая — всех оставшихся ячеек группы, без выполнения остатка.

**Уточнения реализации** (`src/batch/formulas.cpp`, маршрут — `src/server/routes_formulas.cpp`):
- **Запрос**: `calls` — до 10 000 вызовов; `i` — целое; `args` — массив матриц (массивов строк), ячейка — строка, число, boolean или `null`; `X-OF-Workbook` — UUID v4, если передан. Иначе 422 `E_BAD_REQUEST`. Неизвестный `kind` — ошибка вызова `invalidValue`, а не пакета.
- **Без книги** (`X-OF-Workbook` нет) запрос ищется в проектах и примерах, а `meta.missing` не пишется.
- **Аргументы**: больше, чем `@param`, — `invalidValue`; список без непустых ячеек и пустая матрица — пропущенный аргумент.
- **Источник данных**: есть `ready`-экземпляр (§6.3) — читается он, у Oracle- и у Local-запроса одинаково. Нет у Oracle-запроса — `notAvailable` "No data for <id>: refresh it" и запись в `meta.missing` (у `table` и `call`; у `asof` — без записи). Нет у Local-запроса — он вычисляется по текущим данным зависимостей (как Preview, §8.3, без записи результата); зависимость без данных — `notAvailable` и записи в `meta.missing` по §5.3.
- **Значения** (§11.4): `id`, `string`, `text` — строки (длиннее 32 767 символов обрезаются); `integer`, `number`, `decimal` — числа; `date`, `timestamp`, `timestamptz` — серийные числа в `date_system`; `boolean` — `true`/`false`; NULL и NaN/±Inf — `""`. `OF.CALL` с NULL — `notAvailable` "The value is empty". `OF.CALL` по результату не 1 × 1 и `OF.TABLE` больше `ofexcel_spill_max_rows` строк — ошибки из §10.2.
- **`OF.ASOF`** — `fetched_at` экземпляра в локальном времени машины; у вычисляемого Local-запроса — самая ранняя `fetched_at` его зависимостей-запросов и `imported_at` импортов; нет ничего — `notAvailable`.
- **Кэш сервера** — LRU до 512 результатов и 2 000 000 ячеек. Ключ — `kind`, `date_system`, `query_id`, `definition_hash`, подключение, `canonical_params`, версии данных и пользователь Fusion подключения (у Local — пустой). Версии — `data_version` экземпляра, у вычисляемого Local-запроса — `data_version` каждой зависимости (у импорта — из `meta.imports`). Ошибки не кэшируются.
- **Коды ошибок** вызова — по колонке «Excel» §14; `E_BAD_REQUEST` вызова — `invalidValue`, `E_GONE` и прочие без колонки — `notAvailable`.

## 11. Запись в Excel Table

### 11.1 Создание таблицы
1. Колонки: `ColumnInfo[]` запуска. Заголовок — `header`, иначе имя колонки. Пустой — `Column_<n>`. Совпадения без учёта регистра — суффиксы `_2`, `_3`… Длина заголовка — до 255 символов.
2. Перед записью значений — формат колонок:

   | Тип | `numberFormat` |
   |---|---|
   | `id`, `string`, `text` | `@` |
   | `date` | `yyyy-mm-dd` |
   | `timestamp`, `timestamptz` | `yyyy-mm-dd hh:mm:ss` |
   | `decimal(p,s)` | `#,##0` при `s = 0`, иначе `#,##0.` + `s` нулей |
   | `integer` | `0` |
   | `number`, `boolean` | `General` |

3. Таблица создаётся `worksheet.tables.add(range, true)` и получает имя `tbl<QueryId в PascalCase>` с суффиксом при занятости.

### 11.2 Обновление таблицы
1. Дождаться `succeeded`. До этого лист не трогать.
2. Сравнить схему: имена первых `query_columns` колонок таблицы (без учёта регистра) с заголовками нового результата.
   - `strict`: любое отличие в составе или порядке → ничего не писать, ошибка `E_SCHEMA_CHANGED` (на стороне панели) с разницей и кнопкой "Apply new schema".
   - `append`: новые колонки вставляются после колонки `query_columns` (перед пользовательскими), `query_columns` увеличивается; пропавшая колонка → `E_SCHEMA_CHANGED`.
3. Форматы колонок `id`, `string`, `text` ДОЛЖНЫ выставляться в `@` при **каждом** обновлении (иначе Excel превратит `0012` в число). Остальные форматы выставляются только при создании таблицы и для новых колонок; пользовательское форматирование не перезаписывается.
4. Размер: `Table.resize` до `1 + rows` строк (заголовок + данные), если доступен ExcelApi 1.13; иначе удаление лишних строк (`table.rows.getItemAt(i).delete()` порциями с конца) и добавление недостающих (`table.rows.add(null, values)`). При 0 строк таблица сохраняет заголовок и одну пустую строку.
   **После сжатия** строки, которые таблица занимала раньше, ДОЛЖНЫ очищаться (`range.clear(Excel.ClearApplyTo.contents)` для диапазона от новой последней строки до прежней, по всем колонкам таблицы, включая пользовательские): `Table.resize` их не очищает, и старые данные остаются на листе под таблицей (`PHASE0_REPORT.md` §4.8).
5. Значения пишутся порциями по `ofexcel_write_chunk_rows` (по умолчанию 5 000 строк, но не больше ~4 МБ JSON на порцию) только в первые `query_columns` колонок. Размер порции выбран ради прогресса и отзывчивости: в Excel для Mac одна запись 100 000 строк × 14 колонок (15 МБ JSON) прошла за 2,9 с, предела не нашли. Перед каждой порцией — `context.application.suspendApiCalculationUntilNextSync()`.
6. Пользовательские колонки справа от `query_columns`, вычисляемые колонки, стиль таблицы, ссылки формул на таблицу ДОЛЖНЫ сохраняться.
7. После записи — `last_success` в привязке, сохранение `WorkbookPayload`, удаление `partial`.

### 11.3 Ошибки записи
- Ошибка Office.js посередине записи → `partial = { at, run_id }`, баннер "Table partially updated" и кнопка "Retry write" (повтор читает тот же `run_id`; если он вытеснен — `E_GONE` и предложение запустить заново).
- Ошибка запуска → таблица не меняется, баннер с ошибкой и временем `last_success`.

### 11.3a Уточнения реализации
`addin/src/writer/` (решения TASKS.md D4):
- **«Load to table»** сохраняет запрос в книгу (§9.2: запрос привязки — запрос книги), запускает его, ждёт окончания и пишет результат в новую таблицу, левый верхний угол которой — выделенная ячейка активного листа. Занятые ячейки под будущей таблицей — отказ с адресом, лист не трогается. Привязка создаётся с `schema_policy: "strict"` и сохраняется в книге только после того, как таблица создана.
- **Рост** таблицы при обновлении — только на пустые ячейки: если под таблицей что-то есть, отказ с адресом, а не захват чужих данных в таблицу.
- **`append`**: колонки, уже бывшие в таблице, сохраняют место и получают значения по имени (без учёта регистра), даже если запрос вернул их в другом порядке; новые — после них. **«Apply new schema»** берёт колонки результата как есть: колонки запроса добавляются или удаляются на границе с пользовательскими, заголовки переписываются.
- **Строка заголовка** — в формате `@`, чтобы заголовок вида `0012` остался текстом. Таблица без строк — заголовок и одна пустая строка в колонках запроса.
- **Порции** — 5 000 строк и около 4 МБ JSON (значение `ofexcel_write_chunk_rows` по умолчанию; надстройка настройки демона не читает). Страницы `/rows` читаются по 5 000 строк.
- **«Retry write»** читает строки того же `run_id`; если он вытеснен — 410 `E_GONE` и предложение обновить, то есть запустить запрос снова.
- Без ExcelApi 1.13 (`Table.resize`) таблица растёт через `rows.add` и сжимается удалением строк со сдвигом вверх.

### 11.4 Значения
| Тип | Значение в `range.values` |
|---|---|
| `id`, `string` | строка |
| `text` | строка; длиннее 32 767 символов — первые 32 767, в предупреждения запуска на стороне панели "N values truncated in column X" |
| `integer`, `number` | число |
| `decimal` | `Number(строка)` |
| `date` | серийное число: дни от 1899-12-30 (система 1900) или от 1904-01-01 (система 1904) |
| `timestamp`, `timestamptz` | серийное число + доля суток |
| `boolean` | `true` / `false` |
| `null` | `""` |

**Защита от формул в данных.** Строка из результата, начинающаяся с `=`, `+`, `-` или `@`, НЕ ДОЛЖНА стать формулой. Колонки строковых типов имеют формат `@` (п. 11.2.3), и при нём значение сохраняется как текст: проверено для `=…`, `+…`, `-…`, `@…` и `0012` (`PHASE0_REPORT.md` §4.8). Ведущий апостроф для защиты **НЕ ДОЛЖЕН** использоваться: Excel считает его служебным префиксом и удаляет, так что строка `'abc` из данных теряет апостроф в любом формате.

## 12. Импорт таблицы листа
1. Источник — Excel Table (по имени) или диапазон с первой строкой-заголовком.
2. Имя импорта: из имени таблицы → нижний регистр, всё кроме `[a-z0-9_]` → `_`, ведущая цифра → префикс `t_`; длина ≤ 63.
3. Тип колонки определяет панель:
   - формат первой непустой ячейки колонки похож на дату (содержит `y` или `d` и не `@`) → `date`, если у всех значений нулевая доля суток, иначе `timestamp`;
   - все непустые значения — числа, и хоть одно имеет ведущие нули в отображаемом тексте или длину > 15 цифр → `id`;
   - все непустые значения — числа без дробной части, ≤ 15 цифр → `integer`; с дробной частью → `number`;
   - все — `TRUE`/`FALSE` → `boolean`;
   - иначе `string`.

   Пользователь может переопределить тип перед импортом.
4. Передача: `POST /v1/imports` → порции `rows` по 5 000 строк → `commit`. Даты — строками (§3.1).
5. `reimport_before_run: true` → панель повторяет импорт перед каждым запуском Local-запроса, который зависит от этого импорта.

| `ofexcel_status()` | `TABLE(key VARCHAR, value VARCHAR)` | Состояние |

Есть только секрет `oracle_fusion` (созданный в `init.sql`) — добавляет строку с его `ENDPOINT` (схема и хост, без пути) и `REPORT_PATH`, так `init.sql` помечает свои подключения. Запрос выбирается как в §10.2 без книги: проекты, затем примеры. `params` — структура `{имя: значение}`, значения — как JSON от панели (§3.1): числа своим текстом, даты строками, списки массивами. | `ofexcel_call(kind VARCHAR, query VARCHAR, args JSON-строка VARCHAR)` | `VARCHAR` (JSON результата вызова) | Тот же путь, что `/v1/batch`, без книги: запрос — из проектов и примеров, подключение — `@connection`, система дат 1900. Настройки (`SET …`): `ofexcel_port` (INTEGER, 47321), `ofexcel_profile` (`'hosted'`/`'local'`), `ofexcel_hosted_origin` (VARCHAR), `ofexcel_tls_dir` (VARCHAR, пусто = `QEXCEL_HOME/tls`; §8.1), `ofexcel_refresh_parallel` (INTEGER, 4), `ofexcel_run_timeout` (INTEGER секунд, 1800), `ofexcel_spill_max_rows` (INTEGER, 10000), `ofexcel_write_chunk_rows` (INTEGER, 5000), `ofexcel_dataset_ttl_days` (INTEGER, 30), `ofexcel_addin_dir` (VARCHAR, пусто), `ofexcel_projects_dir` (VARCHAR, пусто = `~/QExcel/projects`; §1).

Все настройки `ofexcel_*` регистрируются с областью `GLOBAL`: обычный `SET` в `init.sql` действует на все соединения, включая те, что открывают HTTP-запросы. В DuckDB 2.0 настройка расширения без явной области — сессионная.

**Запуск `ofexceld serve`** ([`--db PATH`] [`--init FILE`] [`--port N`] [`--origin URL`]), по шагам:
1. База — `--db` или `QEXCEL_HOME/data.duckdb`. Имя файла без расширения, совпадающее (без учёта регистра) со схемой `meta`, `ds` или `xl_import`, — отказ `E_BAD_REQUEST` до создания файла: DuckDB называет каталог по имени файла, и `meta.*` стало бы неоднозначным. База открывается с `allow_persistent_secrets = false`: секреты только в памяти (`SPEC.md` §3.1), и поиск секрета по имени не обращается к `~/.duckdb/stored_secrets`, который `enable_external_access = false` запрещает читать.
2. Миграции (§6.2).
3. `init.sql` — `--init` или `QEXCEL_HOME/init.sql`, если файл есть. Названный в `--init`, но отсутствующий файл или ошибка в нём — отказ `E_BAD_REQUEST` с именем файла.
3a. Секреты подключений из `meta.connections` (§8.3) — для строк, чьё имя ещё не занято секретом: секрет из `init.sql` с тем же именем остаётся. Строка, из которой секрет не создаётся, пишется в stderr и пропускается.
3b. Реестр запросов: встроенные примеры, затем проекты из `ofexcel_projects_dir` (его может задать `init.sql`), как `ofexcel_reload()`. Файл, который не разбирается, пишется в stderr и не мешает запуску.
3c. Очистка хранилища (§6.4): экземпляры старше `ofexcel_dataset_ttl_days` (его может задать `init.sql`), заготовки и прерванные запуски. Что удалено, пишется в stderr.
4. Флаги `--port`, `--origin` — поверх значений из `init.sql`.
5. `SET` из `SPEC.md` §8.4. `memory_limit = '2GB'` и `threads = 4` задаются при открытии базы, поэтому `init.sql` может их изменить; остальные — после флагов.
6. `SET lock_configuration = true`; после этого `SET` отказывает в любом соединении.
7. Сервер (§8.1).

stdout — одна строка `listening on https://127.0.0.1:<port>`; строка запуска (версия, база, `init.sql`), остановка и ошибки — в stderr.
