# QExcel — задачи MVP

**Дата:** 2026-10-29 · **Относится к:** `SPEC.md` 0.4 (блок «Объём MVP», §16 фаза 1), `CONTRACTS.md` 1.2, `DECISIONS.md` Р1–Р6

## 0. Как работать с этим документом

- **Одна задача — одна ветка и один pull request.** Ветка `task/<ID>-<кратко>`, например `task/B03-type-contract`. Задачу не начинают, пока не закрыты все её зависимости.
- **Перед началом** прочитать `AGENTS.md`, разделы контракта из поля «Контракт» и код-образцы из поля «Опора».
- **«Готово, когда»** — единственный критерий приёмки. Все перечисленные тесты существуют, проходят локально (`make release && make test && make test_cpp`) и в CI. Векторы из контракта названы в тестах своими идентификаторами (`R12`, `T5`…).
- **«Не делать»** — граница задачи. Что не перечислено в «Сделать», в задачу не входит.
- **Ревью.** Задачи с пометкой 🔒 закрываются только после ревью мейнтейнера (`AGENTS.md`, «Changes that need review»).
- **Остановиться и спросить**, если контракт неоднозначен, противоречит спеке или задаче, нужна новая зависимость, маршрут, настройка или код ошибки, которых нет в контракте, или тест из контракта кажется неверным. Подгонять тест под код нельзя.
- **Отчёт по задаче** — в описании pull request: что сделано; какие тесты добавлены; отклонения от задачи и почему; открытые вопросы.
- Размер: **S** — до дня, **M** — 2–3 дня, **L** — неделя. Задачу размера L разумно разбить на подзадачи внутри ветки.

## 2. Дорожка A — демон

### A1. HTTPS в демоне и локальный CA  [L] 🔒
**Цель.** Демон отвечает только по HTTPS с сертификатом от локального CA в обоих профилях (решение Р6).
**Зависит от:** —
**Контракт:** `CONTRACTS.md` §8.1; `SPEC.md` §12.4; `DECISIONS.md` Р6.
**Опора:** `src/server/http_server.cpp`, `src/main.cpp`, `test/cpp/server_test.cpp`.
**Сделать:**
- vcpkg: включить у `cpp-httplib` фичу `openssl`; сервер — `httplib::SSLServer`.
- `ofexceld install-cert [--dir DIR]`:
  - создаёт в `QEXCEL_HOME/tls/` (или `DIR`) файлы `ca.crt`, `ca.key`, `server.crt`, `server.key`; ключи с правами `0600`;
  - CA: ECDSA P-256, 10 лет, `basicConstraints CA:TRUE, pathlen:0`, `nameConstraints permitted;DNS:localhost, IP:127.0.0.1/255.255.255.255`, CN `QExcel Local CA`;
  - серверный сертификат: ECDSA P-256, 397 дней, SAN `DNS:localhost, IP:127.0.0.1`, `extendedKeyUsage serverAuth`;
  - доверие: macOS — `security add-trusted-cert -r trustRoot -k ~/Library/Keychains/login.keychain-db ca.crt` (через `posix_spawn`, без shell); Windows — `CertAddEncodedCertificateToStore` в `CurrentUser\ROOT`. Флаг `--no-trust` пропускает этот шаг (для CI и тестов).
- `ofexceld uninstall-cert` удаляет CA из доверенных и файлы.
- Настройка `ofexcel_tls_dir` (по умолчанию `QEXCEL_HOME/tls`). `ofexcel_start` без сертификатов в каталоге — `E_UNSUPPORTED: … выполните ofexceld install-cert`.
- При старте: серверный сертификат, у которого осталось меньше 30 дней, перевыпускается от того же CA.
- URL в `ofexcel_start` и `/v1/health`: `https://127.0.0.1:<port>`.
- Дополнить `CONTRACTS.md` §13 строкой `ofexcel_tls_dir` и §8.1 — расположением файлов (в том же pull request).
**Готово, когда:**
- `server_test` работает поверх HTTPS: сертификаты создаются в временном каталоге (`install-cert --no-trust --dir`), клиент проверяет их по `ca.crt`, все прежние проверки G1–G19 проходят. Клиент без `ca.crt` получает ошибку TLS.
- Новый тест: сертификат CA содержит name constraints; серверный — SAN `localhost` и `127.0.0.1`; срок около 397 дней.
- Тест перевыпуска: сертификат со сроком меньше 30 дней перевыпускается при старте, CA не меняется.
- Ручная проверка на Mac (описать в отчёте): `install-cert`, затем `curl https://127.0.0.1:47321/v1/health` без `-k` с `Origin` проходит.
**Не делать:** профиль local и раздачу статики (A2); установщик (E3).

### A2. Профиль local: токен сессии и раздача статики  [M] 🔒
**Цель.** В профиле local демон отдаёт файлы надстройки с того же источника и защищает API токеном сессии.
**Зависит от:** A1.
**Контракт:** `CONTRACTS.md` §8.1 (п. 3), §8.1.1 (G12–G16); `SPEC.md` §5.1, §8.5.
**Опора:** `src/server/request_guard.cpp`, `src/server/routes_health.cpp`.
**Сделать:**
- Токен — 32 байта из `RAND_bytes`, hex, новый при каждом запуске сервера.
- `GET /addin/*` отдаёт файлы из встроенного набора (пока — заглушка `taskpane.html` и `functions.json` из `CONTRACTS.md` §10.1; настоящие файлы подставит E1) или из `ofexcel_addin_dir`, если настройка задана.
- В отдаваемые HTML-файлы токен встраивается как `<meta name="qexcel-session" content="…">`. Маршруты `/addin/*` под проверку `Origin` и токена не попадают; `/v1/*` — попадают.
- `ofexcel_start` в профиле local больше не отклоняется.
**Готово, когда:** HTTP-тест профиля local: G12–G16 на живом сервере; страница `/addin/taskpane.html` содержит токен; `/v1/health` без токена — 401 `E_SESSION`, с токеном — 200; `..` в пути `/addin/` — 404.
**Не делать:** сборку настоящей надстройки (D1, E1).

### A3. База данных, `init.sql` и закрытая конфигурация  [M]
**Цель.** `ofexceld serve` открывает свою базу по умолчанию, выполняет `init.sql` и закрывает конфигурацию в порядке `SPEC.md` §8.4.
**Зависит от:** —
**Контракт:** `CONTRACTS.md` §1 (пути), §6.2; `SPEC.md` §8.4, §12.2.
**Опора:** `src/main.cpp`, `src/meta/migrations.cpp`.
**Сделать:**
- База по умолчанию — `QEXCEL_HOME/data.duckdb` (каталог создаётся). Имя файла не должно совпадать со схемами `meta`, `ds`, `xl_import`: каталог DuckDB называется по имени файла (`PHASE0_REPORT.md`, зонд). Явный `--db` с таким именем — ошибка при старте.
- `init.sql` по умолчанию — `QEXCEL_HOME/init.sql`, если есть.
- Порядок старта: открыть базу → миграции → `init.sql` → флаги командной строки → `SET` из `SPEC.md` §8.4 (включая `memory_limit`, `threads` из настроек) → `lock_configuration = true` → сервер.
- `ofexceld serve` пишет в stderr строку запуска и ошибки; в stdout — только строку «listening on …».
**Готово, когда:** тест (C++ или скрипт в `test/http/`) запускает `ofexceld serve` во временном `QEXCEL_HOME`: создаётся `data.duckdb` с `meta.schema_version = 1`; `SET` после старта из SQL-консоли невозможен (`lock_configuration`); `--db meta.duckdb` отклоняется с понятной ошибкой.
**Не делать:** шифрование базы (A5); подключения (A4).

### A4. Подключения и вход  [M]
**Цель.** Подключения к Fusion хранятся в `meta.connections`, пересоздаются как секреты при старте, вход через SSO доступен по HTTP.
**Зависит от:** A3.
**Контракт:** `CONTRACTS.md` §6.2 (`meta.connections`), §8.3 (`/v1/status`, `/v1/connections`, `/v1/connections/{name}/test`, `/v1/auth/login`, `/v1/auth/logout`), §13 (`ofexcel_set_environment`), §14; `SPEC.md` §3.1; `DECISIONS.md` Р5.
**Опора:** `src/server/routes_health.cpp`, `src/sql_functions.cpp`.
**Сделать:**
- `ofexcel_set_environment(name, environment)`.
- Маршруты из «Контракта». Секрет — `CREATE SECRET <name> (TYPE oracle_fusion, PROVIDER browser, ENDPOINT …, REPORT_PATH …)`. Подключение из `init.sql` с тем же именем имеет приоритет.
- `/v1/auth/login` вызывает `fusion_scanner_sso_login()` для секрета подключения и ждёт до 300 с; одновременно — не больше одного входа на подключение (второй запрос ждёт первый).
- `/v1/status`: `signed_in` и `user` — из `fusion_scanner_sso_status()`.
**Готово, когда:**
- HTTP-тесты: создание подключения (201), повтор имени (409 `E_CONFLICT`), неверное окружение (422), список без секретов в ответе, пересоздание секретов после перезапуска.
- `connections/{name}/test` с подставным транспортом ofquack (как `fusion_seam_test`) — `ok: true`; с транспортом, бросающим ошибку аутентификации, — `E_FUSION_AUTH`.
- Ручная проверка входа на тестовом инстансе — в отчёте.
**Не делать:** интерфейс входа (D2).

### A5. Шифрование базы  [M] 🔒
**Цель.** `data.duckdb` зашифрован, ключ хранится в хранилище ОС.
**Зависит от:** A3.
**Контракт:** `SPEC.md` §8.6.
**Сделать:**
- ключ 32 байта из `RAND_bytes` при первом запуске; macOS — связка ключей (`SecItemAdd`/`SecItemCopyMatching`, служба `QExcel`, учётная запись `data.duckdb`); Windows — файл `QEXCEL_HOME/data.key` под `CryptProtectData` (область текущего пользователя);
- база открывается через `ATTACH … (ENCRYPTION_KEY …)` до миграций;

**Готово, когда:** тест: база, созданная `ofexceld serve`, не открывается в DuckDB без ключа; открывается с ключом из хранилища; удаление ключа из хранилища даёт понятную ошибку при старте с предложением пересоздать кэш (данные — кэш, источник — Fusion).
**Не делать:** шифрование книг Excel.

- ошибка Oracle (`Oracle Fusion rejected the query`) → `E_FUSION_REJECTED`, экземпляр сохраняет прежнюю версию;
- отмена во время «долгой» страницы (транспорт ждёт, пока не вызовут отмену) → `cancelled` не позже 5 с, прежняя версия на месте;
- два запуска подряд → `prev_table` = прежняя версия, более старая удалена;
- повторный запуск того же ключа во время идущего → тот же `run_id`.
**Не делать:** HTTP-маршруты (C4); Local SQL (C5).
