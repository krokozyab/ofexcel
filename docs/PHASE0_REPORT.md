Главные находки:
1. **Oracle `DATE` приходит без времени.** `SYSDATE` отдаётся как `2026-10-29`. Время сохраняется только у `TIMESTAMP` и при `CAST(… AS TIMESTAMP)`. Это тихая потеря данных, требуется решение (§6, Р2).
2. **NULL приходит пустой строкой**, а не NULL. В Oracle пустая строка и NULL — одно и то же, поэтому для Oracle-результатов `''` безопасно читать как NULL (§5, К1).
3. **Пропускная способность ~5 200 строк/с** на 14 колонках, а у каждого запроса есть накладные расходы 1–3,5 с. Миллион строк — около 3,2 минуты загрузки.
4. **Отмена работает** без отдельного процесса.
5. **WebView Excel для Mac не пускает HTTPS-страницу к HTTP API на localhost.** Профиль hosted «статика на HTTPS + API по `http://127.0.0.1` без своего CA» на Mac невозможен. Демону нужен HTTPS с доверенным локальным сертификатом в любом профиле (решение Р6).
6. **Запись в Excel не узкое место:** 500 тыс. строк × 14 колонок пишутся за 13,7 с, а BI Publisher отдаёт их ~96 с.

**Формулы в данных (A6)**

| Значение | Колонка с форматом `@` | Колонка `General` |
|---|---|---|
| `=1+1` | текст `=1+1` | **формула**, значение 2 |
| `=HYPERLINK("https://example.com","x")` | текст | **формула-ссылка** |
| `+1`, `-1`, `-5.5` | текст | числа 1, −1, −5,5 |

Формат `@` защищает от формул и сохраняет ведущие нули. Ведущий апостроф Excel считает служебным префиксом и удаляет в обоих режимах.

**Система дат.** Новая книга — система 1900: `DATE(2026,1,1)` = 46023, что совпадает с нашим пересчётом.
