Главные находки:
1. **Oracle `DATE` приходит без времени.** `SYSDATE` отдаётся как `2026-10-29`. Время сохраняется только у `TIMESTAMP` и при `CAST(… AS TIMESTAMP)`. Это тихая потеря данных, требуется решение (§6, Р2).
2. **NULL приходит пустой строкой**, а не NULL. В Oracle пустая строка и NULL — одно и то же, поэтому для Oracle-результатов `''` безопасно читать как NULL (§5, К1).
3. **Пропускная способность ~5 200 строк/с** на 14 колонках, а у каждого запроса есть накладные расходы 1–3,5 с. Миллион строк — около 3,2 минуты загрузки.
4. **Отмена работает** без отдельного процесса.

## 4. Результаты

### 4.1 Получение данных (BIP → DuckDB)
Запрос: 14 колонок `AP_INVOICE_LINES_ALL`, `ORDER BY invoice_id, line_number`, `FETCH FIRST N ROWS ONLY`, `all_varchar := true`, запись в таблицу DuckDB (`CREATE TABLE … AS`).

| Строк | `fetch_size` | Время | Строк/с |
|---|---|---|---|
| 10 000 | 5 000 | 3,3 с | ~3 000 |
| 100 000 | 5 000 | 24,6 с | ~4 100 |
| 100 000 | 10 000 | 22,8 с | ~4 400 |
| 500 000 | 10 000 | 96,3 с | ~5 200 |

- **Накладные расходы на запрос:** тривиальный запрос к `dual` — 1,3–3,5 с (обычно 2,4–2,8 с). Это нижняя граница времени Preview.
- **`fetch_size` 10 000** быстрее 5 000 примерно на 7 %.
- **Типизация в DuckDB** (приведение 500 000 строк к типам договора) — 0,08 с, на фоне загрузки незаметна.
- **Вход через SSO** — 17–120 с на процесс. Токен живёт около 4 часов. Сохранённая сессия Chrome позволяет входить без участия пользователя, но иногда вход идёт долго.

### 4.2 Форматы значений (`all_varchar := true`)

| Выражение Oracle | Текст от ofquack |

### 4.3 Коллекции `sys.odci*list` (A2)
`odcinumberlist`, `odcivarchar2list`, `odcidatelist` и форма `IN (SELECT … UNION ALL SELECT …)` из `CONTRACTS.md` §4.2 работают через SQL-отчёт. `odcidatelist` хранит `DATE`, поэтому `TIMESTAMP`-элемент теряет время (по той же причине, что в §4.2).

### 4.4 Пустой результат (§5.2)

## 5. Изменения контрактов, которые следуют из замеров

| # | Где | Изменение |
|---|---|---|
| К1 | `CONTRACTS.md` §3.3, §5.1 | Для Oracle-результатов `''` читается как NULL до вывода типов. Oracle не различает их, а ofquack отдаёт NULL пустой строкой |
| К2 | `CONTRACTS.md` §3.3; `SPEC.md` §6.1 | Колонка Oracle `DATE` приходит без времени. Вектор T8 («все `00:00:00` → `date`») в нынешнем виде не срабатывает. Дальнейшее зависит от решения Р2 |
| К3 | `CONTRACTS.md` §3.3 | Время допускается с 1–9 знаками дроби; хранится с точностью до микросекунд (усечение 7–9 знаков) |
| К4 | `CONTRACTS.md` §3.3 | Значения со смещением (`… +00:00`) выводятся как `timestamptz` и приводятся к UTC. Сейчас `timestamptz` — только по объявлению, а такие значения попали бы в `timestamp` с потерей смещения |
| К5 | `CONTRACTS.md` §5.1 | `fetch_size` по умолчанию — 10 000 вместо 5 000 |
| К6 | `CONTRACTS.md` §15–16 | A2, A3, A4, Q2, Q4 подтверждены. Q3 подтверждён с поправками К2–К4. Новое требование к ofquack Q5: в режиме `all_varchar` отдавать NULL как NULL |
| К7 | `SPEC.md` §7.6, §16 | Роль `worker` для отмены в MVP не нужна; остаётся в фазе 2 для изоляции недоверенных определений |
| К8 | `SPEC.md` §12.2 | Размер бинарника — ~67 МБ, а не 55–60 |

## 6. Решения для `DECISIONS.md`

**Приняты 2026-10-29** (`DECISIONS.md`): Р1 — вариант (а), DuckDB 2.0; Р2 — вариант (б), `CAST(col AS TIMESTAMP)` в запросах, модель данных отчёта не меняется; Р3–Р5 — по рекомендациям.

| # | Вопрос | Варианты | Рекомендация |

| Р4 | Предел строк по умолчанию | 1 000 000 (~3,2 мин загрузки) / меньше | Оставить 1 000 000, но показывать прогресс и оценку времени. Пересмотреть после замера записи в Excel |
