# QExcel — спецификация архитектуры

**Версия:** 0.4 (черновик) · **Дата:** 2026-10-29
**Рабочее название продукта:** QExcel. Имя бинарника — `ofexceld`, имя DuckDB-расширения — `ofexcel`.

> **QExcel — рабочая среда для запросов к Oracle Fusion в Excel:** Oracle SQL для получения данных, DuckDB SQL для локального анализа, параметры из ячеек и обновляемые таблицы. Готовые финансовые пакеты (GL, AP, AR) используют то же ядро.

**Изменения относительно 0.3:**
- продукт переформулирован: ядро — подключения, запросы, datasets, обновление и вывод в Excel; GL стал **первым пакетом** на этом ядре (§11), а не основой продукта;
- три режима SQL: Oracle SQL, Local SQL, опубликованный запрос (§4);
- основной результат — **обновляемая Excel Table**, формулы — дополнительный путь (§5);
- MVP — вертикальный сценарий «подключение → SQL → параметры → Preview → таблица → Refresh» (§16); GL-пакет — фаза 2;
- новые разделы: договор о типах данных (§6), модель доступа с честными границами по режимам (§8.2), уровни доверия к определениям (§8.3);
- исправления: полный ключ кэша и сброс клиентского кэша, классификация ошибок при делении пакета, полная замена результата по умолчанию вместо универсального инкремента, полнота данных по dataset'ам вместо пары ledger + period, версия дерева в ключе фильтра GL;
- `OF.SQL` в ячейках по-прежнему не предусмотрен; пересчёт формул **никогда** не ходит в Fusion.

## 0. Ключевые решения (TL;DR)

| Решение | Выбор | Почему |
|---|---|---|
| Основная сущность | **Именованный запрос** с контрактом (параметры, колонки, типы, обновление) → **dataset** → вывод в Excel | Универсально для любых данных Fusion; GL, AP, AR — пакеты поверх |
| Режимы SQL | Oracle SQL (в Fusion через ofquack), Local SQL (DuckDB над datasets и импортированными таблицами), опубликованный запрос | Получение данных отделено от анализа; диалект всегда виден |
| Основной вывод | **Excel Table** с сохранением имени, оформления и формул; `OF.TABLE`/`OF.CALL` — для небольших результатов | Spill зависит от свободного места и даёт `#SPILL!`; большие выгрузки нужны в таблицах |
| Пересчёт и сеть | Формулы читают только локальные datasets; в Fusion ходит только явный Refresh | Пересчёт предсказуем и быстр, присланная книга не выполняет запросы к Fusion сама |
| Фронтенд | Office Web Add-in, XML-манифест, shared runtime; два профиля поставки: **hosted** и **local** (§5.1) | Единственный механизм для Excel на Mac и Windows; hosted снимает свой CA |
| Бэкенд | C++-расширение DuckDB `ofexcel` + `fusion_scanner` (ofquack) + `core_functions` в одном статическом бинарнике | Одна поставка, один тулчейн, прямой доступ к DuckDB без FFI |
| Обновление | По умолчанию — **полная замена** результата с атомарной подменой и сохранением предыдущей версии; инкремент — только по явному контракту | У произвольного SQL может не быть устойчивого ключа |
| Типы данных | Явный договор Oracle → DuckDB → JSON → Excel (§6) | Идентификаторы, `DECIMAL`, даты и NULL нельзя оставлять на волю случая |
| Доступ | Честное разделение: в локальном режиме каталог — удобство, а не защита; настоящее ограничение — отдельные отчёты BIP или серверный режим (§8.2) | Потребитель опубликованного запроса в локальном режиме тоже нуждается в универсальном SQL-отчёте |
| Доверие к определениям | Свои и подписанные — доверенные; запросы из присланных книг — только после подтверждения с показом SQL (§8.3) | Запрос из чужой книги выполнится под вашей учётной записью |
| MVP | Вертикальный сценарий на macOS и Windows; GL-пакет — фаза 2 | Первая польза раньше, риски ядра проверяются на простом сценарии |

## 1. Продукт

### 1.1 Проблема
Получить данные Oracle Fusion в Excel и поддерживать их актуальными — долго и вручную. SQL-эндпоинта у Fusion нет. Остаются OTBI, BI Publisher-отчёты, собранные вручную, и REST API, покрывающий часть схемы. Результат обычно — CSV-выгрузка, которую каждый раз заново вставляют в книгу.

Классические Excel-надстройки для Fusion (SplashBI GL Connect, insightsoftware GL Wand, Blitz Report, ADFdi) в основном построены на Windows-технологиях (`.xll`, COM, VBA, .NET). Power Query есть и в Excel для Mac, но набор источников там уже, чем на Windows, и готового пути «SQL к Fusion» в нём нет. Сравнивать продукт нужно по конкретному пути: подключение к Fusion → запрос → параметры → обновление, а не по утверждению «на Mac ничего нет».

### 1.2 Пользователи

| Роль | Кто | Основной сценарий |
|---|---|---|
| **Автор** | Консультант по Fusion, команда поддержки, SQL-аналитик | Написать запрос, проверить результат, настроить параметры, сохранить и поделиться |
| **Потребитель** | Финансист, бизнес-аналитик | Открыть книгу или выбрать готовый отчёт, указать параметры, обновить |

### 1.3 Основной сценарий
> Аналитик берёт существующий Oracle SQL, получает обновляемую таблицу в Excel, связывает параметры с ячейками и объединяет результат с другими данными без повторных ручных выгрузок.

Пример сверки:
1. `ap_invoices` — Oracle-запрос с параметрами бизнес-единицы и диапазона дат.
2. Его результат сохраняется как локальный dataset.
3. `bank_statement` — таблица банковской выписки, импортированная с листа Excel.
4. `payment_reconciliation` — DuckDB-запрос, объединяющий оба dataset'а.
5. Результат выводится в Excel Table на лист и обновляется одной кнопкой.

### 1.4 Пилоты и метрика
Рыночные выводы — гипотезы, их проверяют три пилота:
1. **Обновляемая AP-выгрузка** — Oracle-запрос с параметрами из ячеек в Excel Table.
2. **Сверка Fusion с внешним файлом** — Oracle-запрос + импорт таблицы листа + Local SQL.
3. **Сравнение TEST и PROD** — один запрос на двух подключениях + Local SQL с разницей.

**Главная метрика — время от установки до первой полезной обновляемой книги.** Дополнительно: время полного Refresh реального отчёта, доля успешных обновлений, число обращений в поддержку на пилот.

### 1.5 Цели
1. Сквозной сценарий §1.3 работает одинаково в Excel на macOS (Apple Silicon) и Windows (Microsoft 365).
2. Автор получает первую обновляемую таблицу из своего SQL без написания макросов, метаданных и pipelines.
3. Потребитель обновляет книгу одной кнопкой и видит, когда и откуда получены данные, сколько строк, не усечён ли результат.
4. Неудачное обновление не портит последний успешный результат.
5. Пересчёт формул не ходит в сеть.
6. Поставка — один исполняемый файл на платформу плюс установщик.

### 1.6 Не цели (для v1)
- Запись в Fusion (журналы, FBDI, ADFdi-сценарии).
- Коннекторы к другим базам, кроме Oracle Fusion.
- Автоматический перевод Oracle SQL в DuckDB SQL.
- SQL в ячейках (`OF.SQL`).
- Замена Smart View / Essbase (ad-hoc pivot по кубу GL Balances).
- Excel в браузере в локальном режиме демона (только в серверном, §13).
- Excel 2016/2019 без подписки.
- macOS x86_64 и Windows ARM64.
- Мультиарендный SaaS.

### 1.7 Позиционирование
- **Ядро:** свой Oracle SQL к Fusion → обновляемая таблица в Excel, параметры из ячеек, локальные сверки и объединения в DuckDB. Одинаково на Mac и Windows.
- **Пакеты:** готовые финансовые функции и отчёты (GL, затем AP и AR) на том же ядре — для потребителей, которые не пишут SQL.
- **Скорость:** локальный пересчёт и локальный SQL не ходят в сеть. Числа о скорости конкурентов в материалы не включаются, пока не измерены самостоятельно.

### 2.1 Почему расширение DuckDB
- **Одна поставка.** DuckDB, ofquack и ofexcel собираются одним CMake и линкуются статически: нет `.duckdb_extension` рядом с бинарником, нет проверки подписи расширений и рассинхрона версий.
- **Без FFI.** Валидация Local SQL — через `duckdb::Parser`, каталог — из `duckdb_functions()` и собственных таблиц, параметры — нативные подготовленные запросы.
- **Тот же тулчейн**, что у ofquack: CMake, vcpkg, extension-ci-tools для `osx_arm64` и `windows_amd64`.
- **Прецедент:** расширение `ui` в DuckDB поднимает локальный HTTP-сервер и отдаёт веб-интерфейс.

Цена: C++ без безопасности памяти и медленнее в разработке, чем Go. Падение роняет демон целиком; в фазе 2 недоверенные определения выполняются в отдельной роли `worker` (§7.6).

### 2.2 Схемы в DuckDB

| Схема | Содержимое |
|---|---|
| `ds` | Datasets: результаты запросов, по таблице на экземпляр (запрос × параметры × подключение) и версию |
| `xl_import` | Таблицы, импортированные с листов Excel |
| `pkg_<name>` | Объекты пакета: `pkg_gl.raw_*`, `pkg_gl.core_*`, макросы пакета |
| `xl` | Опубликованные локальные макросы (функции формул) — из пакетов и личные |
| `meta` | Запросы, версии определений, запуски, экземпляры datasets, доверие, недостающие данные |

## 3. Основные сущности

### 3.1 Подключение
- Подключение — это секрет DuckDB `TYPE oracle_fusion` из ofquack с именем (`fusion_prod`, `fusion_test`) и меткой окружения.
- Метка окружения (`DEV`/`TEST`/`PROD`) задаётся при создании и всегда видна в интерфейсе цветом рядом с каждым запросом, Preview и таблицей.
- Секреты не покидают демон и не сохраняются в книгах. Пароли не используются: `PROVIDER browser` (SSO). `CREATE PERSISTENT SECRET` не используется, потому что пишет секреты на диск открытым текстом; определения подключений (без учётных данных) хранятся в `meta.connections`.
- Книга хранит **имя** подключения и хост, для которого создан запрос. Если у получателя подключение с таким именем указывает на другой хост, панель предупреждает: «Книга создана для fa-xxxx-test, ваше подключение fusion_test указывает на fa-yyyy-test».

### 3.2 Запрос
Запрос — именованное определение с контрактом. Формат — `.sql`-файл с заголовком из строк `-- @ключ: значение`:

```sql
-- @id: ap_invoices
-- @title: Счета AP за период
-- @engine: oracle
-- @connection: fusion_prod
-- @version: 3
-- @param business_unit: integer       | Бизнес-единица (ORG_ID)
-- @param date_from: date              | Дата счёта с
-- @param date_to: date                | Дата счёта по
-- @param status: enum(OPEN,PAID,ALL) = ALL | Статус оплаты
-- @column invoice_id: id
-- @column invoice_num: string
-- @column invoice_amount: decimal(18,2)
-- @column invoice_date: date
-- @refresh: full
-- @max_rows: 500000
SELECT ai.invoice_id, ai.invoice_num, ai.invoice_amount, ai.invoice_date, ai.payment_status_flag
FROM ap_invoices_all ai
WHERE ai.org_id = :business_unit
  AND ai.invoice_date BETWEEN :date_from AND :date_to
  AND (   :status = 'ALL'
       OR (:status = 'PAID' AND ai.payment_status_flag = 'Y')
       OR (:status = 'OPEN' AND ai.payment_status_flag <> 'Y'))
```

| Ключ | Обязателен | Смысл |
|---|---|---|
| `@id` | да | Уникальное имя в проекте/пакете, `[a-z][a-z0-9_]*` |
| `@engine` | да | `oracle` или `local` |
| `@version` | да | Целое; увеличивается при изменении SQL или контракта. Вместе с хешем текста — **версия определения** |
| `@param` | нет | Имя, тип (§6.2), значение по умолчанию, описание |
| `@column` | нет | Явный тип колонки результата. Колонки без объявления получают тип по правилам §6 |
| `@depends` | для `local` | Datasets, от которых зависит запрос, с передачей параметров (§4.2) |
| `@refresh` | нет | `full` (по умолчанию) или `incremental(...)` (§7.3) |
| `@max_rows` | нет | Предел строк; превышение → результат усечён и помечен (§7.4) |
| `@connection` | нет | Подключение по умолчанию |

Формат заголовка общий для запросов ядра и запросов пакетов. Пакеты добавляют свои ключи (`@chunk`, `@target` — §11).

### 3.3 Dataset
- **Экземпляр dataset'а** — результат запроса для конкретных `(запрос, версия определения, подключение, значения параметров)`. Таблица `ds."<id>@<hash>"`.
- Метаданные экземпляра в `meta.dataset_instances`: запрос, версия определения, подключение и окружение, параметры, время получения, число строк, признак усечения, статус, ошибка последнего запуска, версия данных.
- Хранится **текущая** версия и **предыдущая успешная** (§7.2). Старые экземпляры, к которым никто не обращался 30 дней, удаляются (настраивается).

### 3.4 Вывод в Excel (привязка)
Привязка связывает запрос с местом в книге. Хранится в книге (`Office.context.document.customXmlParts`) без секретов:

```json
{ "binding_id": "b-7f3a…",
  "target": {"kind": "table", "sheet": "AP", "table": "tblApInvoices"},
  "query": {"id": "ap_invoices", "version": 3, "hash": "sha256:…", "source": "workbook"},
  "connection": {"name": "fusion_prod", "host": "fa-xxxx.fa.ocs.oraclecloud.com"},
  "params": {"business_unit": {"ref": "Params!B2"},
             "date_from": {"ref": "Params!B3"},
             "date_to":   {"value": "2026-03-31"}},
  "schema_policy": "strict",
  "last_success": {"at": "2026-10-29T09:12:44Z", "rows": 18233, "truncated": false} }
```

Виды вывода: Excel Table (основной), `OF.TABLE` (spill), `OF.CALL` (скаляр) — §5.

### 3.5 Пакет
Пакет — набор запросов, локальных объектов, макросов-функций и тестов с общей предметной логикой:

```
packages/gl/
  package.json        # имя, версия, зависимости, профиль доступа (§8.2), функции
  queries/            # Oracle-запросы загрузки (gl_balances, gl_code_combinations…)
  core/               # Local SQL: представления и служебные макросы
  macros/             # xl-макросы → функции формул (OF.GL_BAL…)
  tests/              # sqllogictest + сверка
```

Встроенные пакеты (GL в фазе 2, AP и AR в фазе 3) вшиваются в бинарник. Корпоративные наборы запросов и макросов распространяются в том же формате с подписью (§8.3).

## 4. Режимы SQL

| Режим | Где выполняется | Диалект | Для чего |
|---|---|---|---|
| **Oracle SQL** | В Fusion через `oracle_fusion_query()` | Oracle | Получение исходных данных |
| **Local SQL** | В DuckDB над datasets, импортированными таблицами и объектами пакетов | DuckDB | Сверки, объединения, локальный анализ |
| **Опубликованный запрос** | Как его движок | Как его движок | Повторное использование коллегами: фиксированная версия, параметры, известная схема; потребитель не редактирует |

В интерфейсе у каждого запроса, в редакторе, в Preview и в истории запусков всегда видно, **где** выполняется SQL и на **каком диалекте** (метка `Oracle · fusion_prod · PROD` или `Local · DuckDB`). Автоматического перевода Oracle SQL в DuckDB нет.

### 4.1 Oracle SQL
- Запрос отправляется через ofquack: тот передаёт его в BI Publisher, где `dbms_xmlgen` выполняет SQL, результат возвращается постранично. Путь только для чтения: записи через BI Publisher нет.
- **Параметры.** У ofquack нет связываемых переменных, поэтому `:name` — это не bind-переменные Oracle. Демон подставляет значения **литералами** строго по типу (§6.2):
  - токенизатор Oracle SQL пропускает строковые литералы (включая `q'[...]'`), комментарии `--` и `/* */` и идентификаторы в кавычках; `:name` заменяется только вне них;
  - `integer`, `number`, `decimal` — проверенное число в каноническом виде;
  - `string` — значение в одинарных кавычках с удвоением `'`; управляющие символы и NUL отклоняются; длина ограничена 4 000 символов;
  - `date` — `DATE 'YYYY-MM-DD'`, `timestamp` — `TIMESTAMP 'YYYY-MM-DD HH24:MI:SS'`;
  - `list<…>` — только после `IN`; подставляется подзапрос по коллекции `sys.odci*list` порциями по 999 элементов, что обходит ORA-01795 (`CONTRACTS.md` §4.2);
  - неизвестный `:name` в тексте — ошибка до отправки.
- Автор отвечает за свой Oracle SQL: продукт его не разбирает и не ограничивает (§8.2). Проверяется только, что после комментариев текст начинается с `SELECT` или `WITH`.

### 4.2 Local SQL
- Выполняется в DuckDB как подготовленный запрос с именованными параметрами (`$name` в тексте — нативные параметры DuckDB, без подстановки литералов).
- Источники: зависимости из `@depends`, таблицы `xl_import.*`, объекты пакетов (`pkg_*`), макросы `xl.*`.
- **Зависимости:**
  ```sql
  -- @id: payment_reconciliation
  -- @engine: local
  -- @param business_unit: integer
  -- @param date_from: date
  -- @param date_to: date
  -- @depends: ap_invoices(business_unit := $business_unit, date_from := $date_from, date_to := $date_to)
  -- @depends: xl_import.bank_statement
  SELECT i.invoice_num, i.invoice_amount, b.amount AS bank_amount,
         i.invoice_amount - coalesce(b.amount, 0) AS diff
  FROM ap_invoices i
  LEFT JOIN bank_statement b ON b.reference = i.invoice_num
  WHERE abs(i.invoice_amount - coalesce(b.amount, 0)) > 0.005
  ```
  Перед выполнением демон находит нужный экземпляр каждой зависимости и создаёт на соединении временные представления с короткими именами (`ap_invoices`, `bank_statement`). Если экземпляра нет или он устарел, запрос не выполняется, а недостающая зависимость попадает в Smart Refresh (§7.5).
- Local SQL проходит валидацию (§8.4): одна инструкция `SELECT`/`WITH`, без чтения файлов и сети, только разрешённые схемы.
- Запросы с зависимостями обновляются цепочкой: Refresh `payment_reconciliation` сначала обновляет `ap_invoices` (если нужно) и повторно импортирует `bank_statement`, если импорт привязан к таблице книги (§5.6).

### 4.3 Опубликованный запрос
- Это запрос (любого движка) с фиксированной версией определения в общем каталоге: в пакете, корпоративном наборе или книге.
- Потребитель видит описание, параметры с подсказками и схему результата, но не редактирует SQL. Изменить можно, сделав свою копию (новый `@id` в проекте).
- Ограничение «не редактирует» — удобство, а не механизм безопасности в локальном режиме (§8.2).

## 5. Excel: интерфейс

### 5.1 Профили поставки надстройки

| | **hosted** | **local** |
|---|---|---|
| Где лежит статика | HTTPS-хостинг (интранет, CDN, GitHub Pages), путь с версией | Вшита в бинарник, `https://localhost:<port>/addin/` |
| Как надстройка ходит в демон | `fetch("http://127.0.0.1:<port>/v1/…")` с CORS | Same-origin |
| Свой корневой CA | Не нужен | Нужен (§12.4) |
| Centralized Deployment в Microsoft 365 | Проходит (публичный HTTPS) | Под вопросом |
| `functions.json` | Статический: функции ядра + функции пакетов, собирается `ofexceld export-addin` | Генерируется демоном, включая личные макросы |
| Офлайн при запуске Excel | Нет | Да |
| Для кого | Корпоративное развёртывание | Консультанты, разработчики, офлайн |

`http://127.0.0.1` по спецификации W3C Secure Contexts считается potentially trustworthy, поэтому запрос из HTTPS-страницы — не mixed content. Но Chromium (а значит, WebView2) ограничивает запросы публичных страниц в локальную сеть (Private Network Access, затем Local Network Access с запросом разрешения). Поведение WebView2 и WKWebView внутри Excel — проверка фазы 0; по её итогам выбирается профиль по умолчанию. Демон поддерживает оба профиля одним бинарником.

Манифест — XML (add-in only), shared runtime (`SharedRuntime 1.1`), namespace функций `OF`.

### 5.2 Сценарий автора
**Подключение → редактор SQL → параметры → Preview → вывод в таблицу → Refresh.**

1. **Подключение.** Выбор или создание подключения (хост, путь к SQL-отчёту BIP, окружение), вход через SSO.
2. **Редактор.** Редактор SQL (CodeMirror 6) с подсветкой для обоих диалектов, переключателем `Oracle | Local` и меткой подключения. Подсказки имён таблиц и колонок Fusion — из словаря ofquack (`oracle_fusion_tables()`, `oracle_fusion_columns()`). Для Local SQL — из каталога DuckDB.
3. **Параметры.** Демон находит `:name`/`$name` в тексте и предлагает объявить их: тип, значение по умолчанию, привязка к ячейке (выбор ячейки на листе) или константа.
4. **Preview.** Кнопка «Preview» — первые 200 строк (одна страница ofquack с `FETCH_SIZE 200`) с типами колонок по договору (§6), временем выполнения и предупреждениями (например, «колонка VENDOR_ID будет выведена как текст»). Preview для Oracle SQL — всегда явная кнопка, никогда не по мере ввода.
5. **Сохранение.** В книгу (по умолчанию, для переносимости) и/или в локальный проект (`~/QExcel/projects/<проект>/queries/`). Секреты не сохраняются.
6. **Вывод.** «Загрузить в таблицу» — новая Excel Table на выбранном листе или существующая таблица (§5.4). Либо «Вставить формулу `OF.TABLE`» для небольших результатов.
7. **Refresh.** Кнопка у привязки, «Обновить лист», «Обновить книгу».

### 5.3 Сценарий потребителя
- **Открыл книгу → проверил параметры → Обновить.** Панель показывает список привязок книги: запрос, подключение и окружение, время последнего успешного получения, число строк, статус.
- Если в книге есть запросы, которые не созданы на этой машине и не входят в доверенные наборы, сначала идёт подтверждение доверия (§8.3).
- **Каталог отчётов** — опубликованные запросы пакетов и корпоративных наборов: выбрать отчёт → заполнить параметры (с подсказками) → «Загрузить в таблицу».

### 5.4 Вывод в Excel Table
**Алгоритм Refresh привязки:**
1. Демон выполняет запрос и **полностью** получает результат в новую версию экземпляра dataset'а (§7.2). Пока результат не получен целиком, лист не трогается.
2. Панель читает результат порциями (`/v1/runs/{id}/rows`) и пишет в таблицу:
   - перед записью — `application.suspendApiCalculationUntilNextSync()`;
   - порции до ~5 000 строк или ~4 МБ JSON, что меньше; конкретные размеры — по замерам фазы 0;
   - размер таблицы приводится к числу строк результата (`Table.resize`), лишние строки удаляются, новые добавляются.
3. После записи — штамп в привязке (`last_success`) и обновление `OF.ASOF`.

**Что сохраняется:** имя таблицы, стиль и форматирование колонок, вычисляемые колонки, которые пользователь добавил справа от колонок запроса, ссылки на таблицу из формул книги.

**Изменение схемы результата** (`schema_policy` привязки):
- `strict` (по умолчанию): если набор или порядок колонок изменился — таблица не трогается, ошибка с описанием разницы и кнопкой «Применить новую схему»;
- `append`: новые колонки добавляются перед пользовательскими вычисляемыми колонками, удалённые колонки — ошибка.

**Ошибки:**
- ошибка выполнения или получения → таблица не трогается, сохраняется последний успешный результат и его время, баннер с ошибкой;
- ошибка во время записи на лист (редко) → привязка помечается «обновлена частично», результат остаётся в демоне, кнопка «Повторить запись».

**Пределы Excel:** 1 048 576 строк × 16 384 колонки, 32 767 символов в ячейке. Результат больше предела листа не выводится, а усекается с явной пометкой (§7.4).

### 5.5 Формулы

| Формула | Возвращает | Назначение |
|---|---|---|
| `=OF.TABLE(query, param1, …)` | матрица (spill) | Небольшой результат: до 10 000 строк (настраивается). Больше — `#N/A` «Результат большой: выведите в таблицу» |
| `=OF.CALL(name, arg1, …)` | скаляр | Скалярный показатель: Local SQL-запрос с результатом 1 × 1 или макрос `xl.*`. Другая форма результата — `#VALUE!` |
| `=OF.ASOF(query_or_table)` | дата-время | Время последнего успешного получения данных |
| `=OF.STATUS()` | строка | `OK` / `NOT_SIGNED_IN` / `STALE` / `OFFLINE` |

Параметры передаются позиционно в порядке `@param`. Пакеты добавляют свои именованные функции (`OF.GL_BAL` и т. д. — §11).

**Пересчёт формул никогда не ходит в Fusion.**
- `OF.TABLE` по Oracle-запросу читает последний экземпляр dataset'а для этих параметров. Если его нет — `#N/A` «Нет данных: обновите», а запрос попадает в Smart Refresh.
- `OF.TABLE`/`OF.CALL` по Local SQL выполняются локально над уже полученными datasets.
- Поэтому присланная книга не выполняет запросы к Fusion при открытии и пересчёте.

Spill зависит от свободного места на листе: занятые соседние ячейки дают `#SPILL!`. Для отчётов переменного размера основной путь — Excel Table.

### 5.6 Импорт таблиц Excel
- «Импортировать таблицу» — выбрать Excel Table или диапазон с заголовком → `xl_import.<имя>`.
- Типы колонок определяются по значениям (число, дата, текст) и могут быть переопределены. Колонки, похожие на идентификаторы (ведущие нули, длина > 15 цифр), по умолчанию — текст.
- Импорт можно привязать к таблице книги: тогда он повторяется перед каждым запуском зависимого Local SQL.
- Передача — порциями тем же путём, что и запись, в обратную сторону.

### 5.7 Сопровождение обновления
- **Прогресс:** страницы и строки, полученные из Fusion; запись на лист.
- **Отмена:** кнопка «Отменить» у запуска. Отменённый запуск не меняет таблицу и dataset.
- **История запусков:** запрос, версия, подключение, параметры, кто, когда, длительность, строки, усечение, результат или ошибка (`/v1/runs?query=`).
- **Свежесть:** время получения у каждой привязки и `OF.ASOF`.
- **Усечение:** явный значок и текст «Показано 500 000 из более чем 500 000 строк (предел запроса)».
- **Последний успешный результат** сохраняется при любой ошибке.

### 5.8 Batcher формул
- Вызовы формул копятся в очереди. Сброс — через 20 мс тишины или при 2 000 вызовах.
- Одинаковые вызовы в пакете схлопываются.
- Каждый запрос несёт `X-OF-Workbook` (GUID книги в `Office.context.document.settings`) — для Smart Refresh.
- **Клиентский кэш** — по ключу из §7.7. Каждый ответ демона несёт `data_version` и `catalog_version`. Панель проверяет `/v1/health` каждые 30 секунд и при возврате фокуса в Excel; при смене любой версии клиентский кэш сбрасывается и выполняется пересчёт затронутых формул.

### 5.9 Ошибки → коды Excel

| Ситуация | Excel | `CustomFunctions.ErrorCode` |
|---|---|---|
| Неверный тип или значение параметра | `#VALUE!` | `invalidValue` |
| Неизвестный запрос или функция | `#NAME?` | `invalidName` |
| Нет данных (экземпляр dataset'а не получен) | `#N/A` + «Нет данных: обновите» | `notAvailable` |
| Результат больше предела spill | `#N/A` + «Выведите в таблицу» | `notAvailable` |
| Демон недоступен / нет входа | `#N/A` + пояснение | `notAvailable` |
| Внутренняя ошибка SQL | `#N/A` + текст ошибки (усечённый) | `notAvailable` |

## 6. Договор о типах данных

### 6.1 Колонки результата
Тип колонки определяется так: явный `@column` → тип, уже закреплённый за этим определением запроса (может только расширяться) → вывод по значениям **полного** результата. Итог фиксируется в схеме и показывается в Preview.

Oracle-типы колонок демону недоступны: ofquack получает результат через `dbms_xmlgen` как текст, и демон забирает его с `all_varchar := true`. Поэтому колонка «Источник в Oracle» ниже — ориентир, а точный алгоритм вывода по значениям — в `CONTRACTS.md` §3.3.

Фаза 0 показала две особенности (`PHASE0_REPORT.md` §4.2): NULL приходит пустой строкой и для Oracle-результатов читается как NULL, а колонка Oracle `DATE` приходит **без времени** (`YYYY-MM-DD`). По решению Р2 (`DECISIONS.md`) модель данных отчёта не меняется: время из `DATE` получают через `CAST(col AS TIMESTAMP)`, а редактор подсказывает это у колонок типа `date`.

| Тип в договоре | Источник в Oracle | DuckDB | JSON (демон → панель) | Excel |
|---|---|---|---|---|
| `id` | `NUMBER` без дробной части в колонках `*_ID`, `*_NUM` (если объявлено), или явный `@column … : id` | `VARCHAR` | строка | **Текст** (`numberFormat "@"`), без экспоненты и потери цифр |
| `integer` | `NUMBER(p,0)`, p ≤ 15 | `BIGINT` | число | Число |
| `decimal(p,s)` | `NUMBER(p,s)`, s > 0, и суммы | `DECIMAL(p,s)` | **строка** с десятичной точкой (`"1234.56"`) | Число (double); формат с `s` знаками |
| `number` | `NUMBER` без точности, `BINARY_DOUBLE` | `DOUBLE` | число | Число |
| `string` | `VARCHAR2`, `CHAR`, `NVARCHAR2` | `VARCHAR` | строка | Текст |
| `text` | `CLOB` | `VARCHAR` | строка, ≤ 32 767 символов | Текст; длиннее — усечение с пометкой в колонке и в истории запуска |
| `date` | `DATE` без времени (все значения в 00:00:00) | `DATE` | `"YYYY-MM-DD"` | Серийная дата, формат даты |
| `timestamp` | `DATE` со временем, `TIMESTAMP` | `TIMESTAMP` | `"YYYY-MM-DD HH:MM:SS"` | Серийная дата-время |
| `timestamptz` | `TIMESTAMP WITH TIME ZONE` | `TIMESTAMPTZ` | ISO 8601 в UTC | Дата-время в UTC, в заголовке колонки пометка «UTC» |
| `boolean` | — (в Oracle обычно `'Y'/'N'`) | `BOOLEAN` | `true/false` | `TRUE/FALSE` |

Правила:
- **Идентификаторы никогда не превращаются в числа автоматически.** Fusion-идентификаторы бывают длиной 15+ цифр, а Excel хранит числа как double (около 15 значащих цифр). Колонка `NUMBER(…,0)` длиной больше 15 цифр без явного объявления получает тип `id`.
- **`DECIMAL` передаётся строкой**, чтобы JSON не терял точность. Панель превращает её в число при записи на лист. Вычисления и агрегаты в DuckDB точные (`DECIMAL`); в Excel значение — double.
- **Точность.** Обещание «совпадает до копейки» означает: каждое значение в ячейке равно значению Fusion, округлённому до его масштаба, а агрегаты, посчитанные в DuckDB, точные. Суммы, которые пользователь считает формулами Excel, подчиняются арифметике double, и продукт за них не отвечает.
- **Часовые пояса.** Oracle `DATE` и `TIMESTAMP` без пояса не пересчитываются: выводятся как есть. Какие колонки Fusion хранятся в UTC (как правило, `creation_date`, `last_update_date`), указывается в описании запроса или пакета, а не угадывается.
- **NULL и пустая строка.** Oracle не различает `''` и `NULL`. В DuckDB они различаются, но в Excel оба выглядят пустой ячейкой. Для `OF.CALL` скалярный `NULL` → `#N/A`. Для Local SQL, где важна разница, используется явное `coalesce`.
- **Дата без времени** определяется по Preview и по полному результату: если хоть одно значение содержит время, колонка — `timestamp`. Тип фиксируется в схеме экземпляра; при изменении между запусками — правило `schema_policy` (§5.4).

### 6.2 Параметры

| Тип | Ввод из ячейки Excel | Oracle (литерал) | Local (параметр DuckDB) |
|---|---|---|---|
| `integer` | число без дробной части или текст из цифр | `12345` | `BIGINT` |
| `number`, `decimal` | число или текст с точкой | `1234.56` | `DOUBLE` / `DECIMAL` |
| `string` | любое значение → текст | `'O''Brien'` | `VARCHAR` |
| `id` | текст из цифр (число → текст без экспоненты) | `300000012345678` | `VARCHAR` |
| `date` | серийная дата Excel или `YYYY-MM-DD` | `DATE '2026-03-31'` | `DATE` |
| `timestamp` | серийная дата-время или ISO | `TIMESTAMP '2026-03-31 23:59:59'` | `TIMESTAMP` |
| `boolean` | `TRUE/FALSE`, `Y/N`, `1/0` | `'Y'`/`'N'` (по объявлению) | `BOOLEAN` |
| `enum(A,B,…)` | одно из значений | `'A'` | `VARCHAR` |
| `list<T>` | диапазон ячеек или текст через запятую | `(…)`, порции по 1 000 | `T[]` |

Пустая ячейка → значение по умолчанию, если оно объявлено; иначе ошибка параметра. Пакеты добавляют семантические типы (`ledger`, `period`, `filter`… — §11.3).

## 7. Выполнение, хранение и обновление

### 7.1 Запуск
- Запуск (`run`) — выполнение запроса с параметрами на подключении. Результат пишется в **новую** версию экземпляра dataset'а.
- Oracle-запросы выполняются на отдельном соединении DuckDB через `oracle_fusion_query()`; параллельно — не больше `ofexcel_refresh_parallel` запусков (по умолчанию 4).
- Local-запросы выполняются в пуле соединений.
- Прогресс (страницы, строки) обновляется в `meta.runs` и отдаётся `/v1/runs/{id}`.

### 7.2 Полная замена (по умолчанию)
1. Результат грузится в `ds."<id>@<hash>__v<N+1>"`.
2. После успешного получения — в одной транзакции экземпляр переключается на новую версию; предыдущая успешная версия сохраняется как `__prev`, более старые удаляются.
3. При ошибке или отмене новая версия удаляется, экземпляр продолжает указывать на последнюю успешную.
4. `data_version` экземпляра увеличивается только при успешной подмене.

### 7.3 Инкрементальное обновление (только по явному контракту)
Для произвольного SQL инкремент не универсален: результат может содержать агрегаты, join'ы и вычисляемые колонки без устойчивого ключа. Поэтому он включается только явно:

```sql
-- @refresh: incremental(key = invoice_id, watermark = last_update_date, deletes = full_key_scan)
```

- `key` — колонки устойчивого ключа. Сравнение nullable-колонок ключа — через `IS NOT DISTINCT FROM`. После каждого запуска проверяется уникальность ключа; дубликаты — ошибка запуска.
- `watermark` — монотонная колонка (обычно `last_update_date`). В запрос подставляется `:__watermark` — последний максимум.
- `deletes` — как обнаруживать удалённые в источнике строки:
  - `none` — удаления не отслеживаются (только для источников, где строки не удаляются; это нужно указать осознанно);
  - `full_key_scan` — отдельный лёгкий запрос всех ключей раз в N запусков (по умолчанию каждый 10-й) и удаление отсутствующих;
  - `soft_delete(column)` — признак удаления в самих данных.
- Без явного контракта — полная замена.

### 7.4 Пределы и усечение
- `@max_rows` запроса (по умолчанию 1 000 000 для вывода в таблицу и 10 000 для `OF.TABLE`).
- При превышении демон прекращает получение страниц, помечает экземпляр как `truncated = true` и записывает это в историю. Интерфейс всегда показывает усечение явно (§5.7).

### 7.5 Полнота данных и Smart Refresh
- Полнота определяется **по экземплярам dataset'ов**, а не по общим параметрам. Каждый Local-запрос и каждая функция пакета объявляют зависимости (`@depends`), а демон проверяет, что каждый нужный экземпляр получен и не устарел.
- Пакеты могут объявить **области** внутри dataset'а (например, GL — порции `ledger × period` для `gl_balances`, §11.6). Полнота тогда проверяется по областям.
- Каждая недостающая зависимость или область записывается в `meta.missing(workbook_id, query_id, params, first_seen, last_seen, requests)`.
- Панель показывает «Не хватает данных для этой книги: ap_invoices (BU 204, Jan–Mar 2026) [Обновить]» и обновляет всё одной кнопкой, в порядке зависимостей.

### 7.6 Отмена и процесс-исполнитель
- Отмена — `Connection::Interrupt()` на соединении запуска.
- Фаза 0 подтвердила: `Connection::Interrupt()` прерывает идущий сетевой вызов ofquack за 0,2–0,3 с, и соединение остаётся рабочим (`PHASE0_REPORT.md` §4.5). Поэтому в MVP Oracle-запуски выполняются в процессе демона, а процесс-исполнитель для отмены не нужен.
- Роль `worker` также используется в фазе 2 для выполнения недоверенных определений с ограничениями ОС (§8.4).

### 7.7 Кэш результатов формул
Ключ серверного LRU и клиентского кэша:

```
(функция или запрос, аргументы, версия определения, подключение и окружение,
 контекст пользователя, версии всех зависимых экземпляров dataset'ов)
```

- Версия определения = `@version` + хеш текста (меняется при правке макроса или запроса).
- Контекст пользователя — имя пользователя Fusion текущей сессии (важно при смене входа).
- Любое изменение одного из компонентов даёт промах кэша. Клиентский кэш сбрасывается по `data_version`/`catalog_version` (§5.8).

### 7.8 Вычисление пакета формул (`/v1/batch`)
1. Подстановка значений на диапазоны (для функций пакетов с матричными параметрами — §11.2).
2. Проверка полноты зависимостей (§7.5): ячейки без данных сразу получают `notAvailable`.
3. Группировка по `(функция, набор переданных аргументов)` → один подготовленный запрос на группу с `LIST`-параметрами и `unnest`.
4. **Классификация ошибок:**
   - ошибка данных (преобразование типа, неверный аргумент, ошибка внутри выражения) — группа делится пополам и пересчитывается, чтобы локализовать ячейки;
   - нехватка памяти, тайм-аут, отмена, ошибка схемы или связывания (Binder/Catalog), недоступность зависимости — **без деления**: ошибка у всей группы сразу;
   - общий бюджет повторов на пакет: не больше 2 × число групп дополнительных запросов и не больше 2 секунд; после исчерпания оставшиеся ячейки получают ошибку.
5. Аргументы из ячеек никогда не попадают в текст SQL — только в значения параметров.

## 8. Доступ и безопасность

### 8.1 Модель угроз

| # | Угроза | Мера |
|---|---|---|
| T1 | Потребитель получает данные шире, чем ему положено | Честные границы по режимам (§8.2); профили доступа пакетов; отдельные отчёты BIP или серверный режим для настоящего ограничения |
| T2 | Присланная книга выполняет чужой Oracle SQL под вашей учётной записью, и результат возвращается отправителю вместе с книгой | Подтверждение доверия с показом SQL и таблиц (§8.3); пересчёт не ходит в Fusion (§5.5) |
| T3 | Чужое определение Local SQL читает файлы или выходит в сеть | Валидация (§8.4), выключенный внешний доступ, заблокированная конфигурация; фаза 2 — изоляция ОС в `worker` |
| T4 | Сайт в браузере обращается к localhost API | Проверка `Host` и `Origin`, CORS только для своего origin, только `127.0.0.1` (§8.5) |
| T5 | Кража ноутбука | Шифрование `data.duckdb`, ключ в Keychain / DPAPI |
| T6 | Утечка токена Fusion | Токен только в памяти (ofquack), логи без секретов |
| T7 | Подмена или догрузка расширений | Статическая линковка; автозагрузка, автоустановка и community-расширения выключены |
| T8 | Запрос к PROD по ошибке вместо TEST | Метка окружения везде; предупреждение при несовпадении хоста книги и подключения (§3.1) |

### 8.2 Модель доступа: что реально ограничивается

| Режим | Что нужно потребителю в Fusion | Что он реально может | Чем ограничен |
|---|---|---|---|
| **Локальный демон + универсальный SQL-отчёт BIP** (MVP) | Доступ к SQL-отчёту, через который работает ofquack | Выполнить **любой** SQL, на который у отчёта есть права | Только правами самого отчёта. Каталог опубликованных запросов и запрет редактирования — **удобство**, не защита |
| **Опубликованный запрос как отдельный отчёт BIP** (фаза 2) | Доступ только к этому отчёту | Только этот запрос со своими параметрами | Правами отчёта BIP. Построчные ограничения — только если их реализует модель данных отчёта |
| **Серверный режим с сервисной учётной записью** (фаза 3) | Ничего, кроме входа через Entra ID | Только запросы каталога, разрешённые ему на сервере | Авторизацией сервера по запросу + построчными фильтрами пакетов |

Выводы:
- **Доступ к универсальному SQL-отчёту BIP — существенное полномочие.** Его получают только авторы. Это нужно прямо написать в документации для заказчика и выдавать отдельной ролью.
- В MVP продукт **не обещает** ограничивать потребителя сильнее, чем права SQL-отчёта, и не обещает соответствия всем правам пользователя в Fusion.
- Построчная безопасность **не универсальна.** Добавить фильтр к чужому произвольному SQL надёжно нельзя: остаются подзапросы, CTE, объединения и другие источники. Поэтому построчные ограничения реализуют **пакеты** в своих контролируемых запросах, и каждый пакет явно объявляет свой профиль доступа в `package.json`:
  - GL — Data Access Sets (§11.8);
  - AP, AR — бизнес-единицы из назначений данных пользователя (уточняется при разработке пакетов);
  - пакет без профиля доступа помечается в каталоге как «без построчных ограничений».
- **Публикация как отдельный отчёт BIP** (фаза 2): кнопка «Опубликовать в BIP» создаёт модель данных и отчёт в каталоге BI Publisher через его веб-сервисы, а привязки потребителей указывают на этот отчёт. Осуществимость и сопровождение — открытый вопрос (§19).

### 8.3 Доверие к определениям

| Источник определения | Уровень | Что требуется перед выполнением |
|---|---|---|
| Создано в редакторе на этой машине | доверенное | — |
| Встроенный пакет (вшит в бинарник) | доверенное | Подпись сборки |
| Корпоративный набор | доверенное | Валидная ed25519-подпись ключом из `init.sql` |
| Из книги, создано другим, хеш неизвестен | **недоверенное** | Подтверждение пользователя |

- Подтверждение показывает: автора и дату (из метаданных книги), подключение и окружение, **полный текст SQL** каждого запроса, список таблиц Fusion, к которым обращается запрос (по простому разбору `FROM`/`JOIN`), и предупреждение: «Запрос выполнится под вашей учётной записью. Если вы сохраните и отправите книгу, полученные данные уйдут вместе с ней».
- Подтверждённые хеши определений записываются в `meta.trusted_definitions`. При изменении текста (новый хеш) подтверждение запрашивается снова.
- До подтверждения запросы книги не выполняются, а формулы по ним возвращают `#N/A` «Запрос не подтверждён».
- Сам SQL определения в книге переносится вместе с ней. Поэтому коллега получает **и** определение, **и** привязку. Функции пакетов переносятся, если у коллеги установлен тот же пакет; иначе панель сообщает, какого пакета не хватает.

### 8.4 Изоляция исполнения
- **AST-валидатор — дополнительная защита, а не песочница.** DuckDB прямо рекомендует для недоверенных запросов изоляцию на уровне ОС и предупреждает, что настройки движка её не заменяют. Поэтому:
  - Local SQL из **недоверенного** источника не выполняется без подтверждения (§8.3);
  - в фазе 2 недоверенные Local-определения выполняются в процессе `worker` с ограничениями ОС (macOS: запуск без сетевых прав и с доступом только к своему временному каталогу; Windows: Job Object + низкий уровень целостности). Конкретные механизмы — проверка фазы 2.
- **Валидация Local SQL** (`duckdb::Parser`, обход AST):
  - одна инструкция `SELECT` или `WITH … SELECT`;
  - запрещены `oracle_fusion_query`, `fusion_scanner_*`, `ofexcel_*`, `read_*`, `glob`, `query`, `query_table`, `getenv`, любые табличные функции чтения файлов;
  - разрешены только временные представления зависимостей, `xl_import.*`, `pkg_*.core_*`, `xl.*` и встроенные функции;
  - запрещены `ATTACH`, `COPY`, `INSTALL`, `LOAD`, `SET`, `PRAGMA`.
- **Настройки демона** после инициализации:
  ```sql
  SET autoinstall_known_extensions = false;
  SET autoload_known_extensions = false;
  SET allow_community_extensions = false;
  SET enable_external_access = false;
  SET memory_limit = '2GB';
  SET threads = 4;
  SET lock_configuration = true;
  ```
  ofquack ходит в сеть через собственный curl-транспорт, поэтому `enable_external_access = false` его не блокирует. Именно поэтому `oracle_fusion_query` запрещён в Local SQL на уровне валидации.
- **SQL по сети принимает только автор.** Текст SQL принимают только маршруты редактора (`/v1/preview`, `/v1/queries`), и только от своей надстройки (§8.5). Формулы передают лишь имя запроса или функции и аргументы.

### 8.5 Локальный API
Общее:
- только `127.0.0.1:<port>` (по умолчанию `47321`);
- `Host` — `localhost:<port>` или `127.0.0.1:<port>` (защита от DNS rebinding);
- без cookie.

**local:** HTTPS, same-origin, `Origin` = собственный origin, сессионный токен (`RAND_bytes`) встраивается в отдаваемые страницы и обязателен в `X-OF-Session`.

**hosted:** HTTP на `127.0.0.1`.
- `Origin` должен точно совпадать с `ofexcel_hosted_origin`. Остальные — 403 без CORS-заголовков.
- Preflight `OPTIONS`: `Access-Control-Allow-Origin: <hosted_origin>`, `Access-Control-Allow-Headers: Content-Type, X-OF-Workbook, X-OF-Session`, `Access-Control-Allow-Private-Network: true` (для WebView со старым механизмом PNA).
- В MVP — проверка `Origin` и `Host`. В фазе 2 — сопряжение: при первом подключении демон открывает локальную страницу «Разрешить надстройке доступ», после чего надстройка получает токен и хранит его в `OfficeRuntime.storage`.

### 8.6 Данные на диске
- `data.duckdb` шифруется (`ATTACH … (ENCRYPTION_KEY …)`); ключ — в macOS Keychain (`SecItemAdd`/`SecItemCopyMatching`) или в файле под DPAPI (`CryptProtectData`) на Windows.
- Опция «не хранить на диске» — in-memory режим.
- Книги Excel с выведенными данными защищаются средствами самого Office; продукт об этом предупреждает в подтверждении доверия (§8.3).

## 11. Пакет GL (фаза 2)

GL — первый пакет на ядре. Всё, что в 0.3 было основой продукта, теперь живёт здесь.

### 11.1 Состав
- Oracle-запросы загрузки: `gl_balances`, `gl_code_combinations`, `gl_ledgers`, `gl_periods`, `seg_values`, `seg_hier_cf`, `tree_versions`, `user_access`.
- Local-объекты (`pkg_gl.core_*`): балансы с вычисленными PTD/QTD/YTD, сегменты, иерархии, компилятор фильтров.
- Функции формул: `OF.GL_BAL`, `OF.GL_BAL_SEG`, `OF.GL_TB`, `OF.GL_PERIOD_OFFSET`, `OF.GL_ACCOUNT_DESC`; затем `OF.GL_VARIANCE`.
- Профиль доступа: Data Access Sets (§11.8).
- Опубликованные запросы: Trial Balance, обороты по счёту, журналы по счёту (drill).

### 11.2 Функции и форма вызова
- **Позиционные сегменты.** Для каждой функции с параметром `filter` генерируется вариант `_SEG`: `=OF.GL_BAL_SEG($B$1; C$2; "YTD"; "TOTAL"; $A5; $B5; "*"; $D5)`. Сегменты — repeating-параметр в порядке плана счетов ledger'а; каждый понимает мини-синтаксис фильтра (`101`, `4000-4999`, `4*`, `!4500`, `P:TOTAL_REVENUE`); пустое значение или `*` — все значения. Демон переписывает вызов в канонический фильтр. Форма «весь ряд `A5:F5` как список сегментов» не поддерживается: она неотличима от подстановки по диапазону.
- **Динамические массивы.** Параметры функций пакета объявлены с `dimensionality: "matrix"`, результат — `matrix`; подстановка по правилам NumPy (1 × 1 — во все ячейки, строка растягивается вниз, столбец — вправо, несовместимые формы — `#VALUE!`). `=OF.GL_BAL($B$1; C$2:N$2; $A5:$A200; "PTD")` — одна формула на матрицу, один вызов в демон. Поведение в Excel Mac/Win — проверка фазы 0 GL; запасной вариант — отдельные варианты `_A`.
- Строковый фильтр (`"ACCOUNT=4000-4999,!4500;COMPANY=101"`) остаётся для сложных выборок.

### 11.3 Семантические типы параметров
`ledger`, `period`, `filter`, `segment(NAME)`, `enum(…)` поверх типов ядра (§6.2). На них построены:
- конструктор формул в панели: ledger'ы — только доступные по DAS, периоды — по календарю ledger'а, поиск по значениям сегментов, выбор узлов дерева;
- предкомпиляция фильтров (§11.4);
- генерация `_SEG`;
- полнота по областям `ledger × period` (§11.6).

### 11.4 Компиляция фильтров счетов
Скалярный предикат с фильтром-колонкой нельзя превратить в hash join, поэтому фильтры компилируются заранее:

```sql
CREATE TABLE pkg_gl.core_filter_specs (
    spec VARCHAR, coa_id BIGINT, tree_code VARCHAR, tree_version_id VARCHAR,
    compiled_at TIMESTAMP, PRIMARY KEY (spec, coa_id, tree_code, tree_version_id));
CREATE TABLE pkg_gl.core_filter_ccids (
    spec VARCHAR, coa_id BIGINT, tree_code VARCHAR, tree_version_id VARCHAR, ccid BIGINT);
```

- **Версия дерева в ключе.** Термы `P:VALUE` раскрываются по дереву, а версия дерева выбирается по дате периода (§11.7). Один и тот же фильтр для двух исторических периодов может означать разные наборы счетов, поэтому `tree_code` и `tree_version_id` входят в ключ. Для фильтров без родительских значений они равны `''`.
- `pkg_gl.acct_match(spec, coa_id, tree_code, tree_version_id, ccid)` — `EXISTS` по равенству всех колонок; `pkg_gl.spec_ready(...)` — проверка, что фильтр скомпилирован (иначе макрос возвращает `NULL` → `#N/A`, а не тихий ноль).
- Компиляция — перед каждым пакетом формул для фильтров из аргументов и после каждого обновления для литералов в макросах. Обновление плана счетов или деревьев очищает обе таблицы.
- Фильтр внутри макроса — только параметр или строковый литерал; склейку строк валидатор отклоняет.
- Для контролируемых макросов пакета план пакетного запроса проверяется тестом `EXPLAIN` на отсутствие nested loop join. Для пользовательских запросов такой проверки нет: для них проверяются корректность и время на типичной нагрузке.

### 11.5 Данные и вычисления
- Колонок PTD/YTD в `GL_BALANCES` нет:
  ```
  ptd = period_net_dr - period_net_cr
  begin_bal = begin_balance_dr - begin_balance_cr
  qtd = (quarter_to_date_dr - quarter_to_date_cr) + ptd
  ytd = begin_bal + ptd
  ltd = (project_to_date_dr - project_to_date_cr) + ptd
  ```
- **Типы валют — гипотеза для сверки:**

  | `currency_type` | Гипотеза условия | Суммы |
  |---|---|---|
  | `TOTAL` | `currency_code` = валюта ledger'а, `translated_flag IS NULL` | Итог в валюте ledger'а |
  | `ENTERED` | `currency_code` ≠ валюта ledger'а, `translated_flag` ∈ (`'R'`, `'N'`) | `period_net_*` — в валюте операции; `*_BEQ` — эквивалент только этих операций |
  | `TRANSLATED` | `translated_flag = 'Y'` | Результат Translation |
  | `STAT` | `currency_code = 'STAT'` | Статистические суммы |
  | `UNKNOWN` | остальное | Ненулевое число строк — ошибка теста сверки |

  Значения `translated_flag` взяты из опыта EBS и не подтверждены для Fusion.

### 11.6 Загрузка и целостность
- Запрос `gl_balances` — с порциями `ledger × period` (`@chunk`), инкрементальный по явному контракту: ключ `ledger_id, code_combination_id, currency_code, period_name, actual_flag, translated_flag, encumbrance_type_id` (последние два — через `IS NOT DISTINCT FROM`), водяной знак `last_update_date`, `deletes = none` (строки балансов не удаляются — подтвердить в фазе 0 GL).
- **Области:** каждая порция `ledger × period` — область dataset'а `gl_balances`; полнота функций GL проверяется по областям (§7.5).
- **Целостность плана счетов:** `gl_code_combinations` — зависимость `gl_balances` и обновляется перед ним по `last_update_date`. После загрузки балансов — проверка CCID без комбинации (`ANTI JOIN`), догрузка по списку порциями по 1 000. Если недостающие остались, затронутые области не помечаются загруженными.
- Закрытые периоды (по `GL_PERIOD_STATUSES`) повторно не загружаются без явного запроса.

### 11.7 Иерархии
- Источник — `GL_SEG_VAL_HIER_CF` (уровни `DEP0..DEP31_PK1_VALUE`, `TREE_CODE`, `TREE_VERSION_ID`, `DISTANCE`). В DuckDB — `pkg_gl.core_seg_hier(tree_code, tree_version_id, ancestor, descendant, depth)` через UNPIVOT.
- Направление уровней (где корень) уточняется по `DISTANCE`.
- Версия дерева по умолчанию — действующая на дату окончания периода; дерево по умолчанию для сегмента — в `pkg_gl.meta_coa_trees`.

### 11.8 Профиль доступа: Data Access Sets
- Цепочка: `PER_USERS` → `PER_USER_ROLES` (активные, не прекращённые) → `PER_ROLES_DN` → `FUN_USER_ROLE_DATA_ASGNMNTS` (`ACTIVE_FLAG = 'Y'`, роль активна у пользователя) → объединение `ACCESS_SET_ID`/`LEDGER_ID` по всем ролям.
- Фильтр — подзапрос `EXISTS` к `GL_ACCESS_SET_NORM_ASSIGN` на стороне Oracle (литералом — только короткий список id access set'ов): доступ ко всему ledger'у, к значению сегмента или к родительскому значению через `GL_SEG_VAL_HIER_CF`. Так не возникает ORA-01795, и родительские значения раскрываются в Oracle.
- Если права определить не удалось — загрузка запрещена (fail closed).
- Ограничение действует **внутри пакета GL**. Оно не распространяется на собственные Oracle-запросы автора и не делает потребителя ограниченнее прав SQL-отчёта (§8.2).

### 11.9 Smart Refresh для GL
Недостающие области `ledger × period` из пакетов формул сворачиваются в диапазоны: «US Primary Ledger — Jan-26…Mar-26 [Загрузить]».

### 11.10 Фаза 0 пакета GL (до начала фазы 2)
1. Сверка вычислений и таблицы типов валют с Trial Balance Fusion (2 ledger'а × 3 периода, иностранная валюта, translation, STAT): совпадение до копейки, ноль `UNKNOWN`.
2. Соглашение уровней `GL_SEG_VAL_HIER_CF`, источник версий деревьев.
3. Цепочка DAS: колонка сопоставления `ROLE_NAME` с `PER_ROLES_DN`, наследование ролей, коды `SEGMENT_VALUE_TYPE_CODE` и `ALL_SEGMENT_VALUE_FLAG`, рабочий шаблон фильтра.
4. Матричные параметры и repeating-параметр в Excel Mac/Win.
5. План пакетного запроса с `acct_match` — hash join; размер `core_filter_ccids` на реальном плане счетов.
6. Лимиты BIP на порцию `GL_BALANCES`.

### 11.11 Приёмка пакета GL
- Сверка `GL_BAL`/`GL_TB` с Trial Balance Fusion — 100 % на тестовом наборе, ноль `UNKNOWN`.
- 5 000 скалярных формул — < 3 с; массив 200 × 12 — < 1 с (тёплый кэш, M-серия).
- Новая комбинация счетов в открытом периоде попадает в баланс после инкрементального обновления.
- Повторная загрузка порции не создаёт дубликатов.
- Пользователь без доступа к ledger'у или сегменту не получает его строк.
- Отчёт с позиционными сегментами собирается в конструкторе без ручного ввода фильтров.

### 11.12 Пакеты AP и AR (фаза 3)
- AP: счета, платежи, поставщики, открытые позиции; профиль доступа — бизнес-единицы из назначений данных пользователя.
- AR: транзакции, поступления, aging; профиль доступа — бизнес-единицы.
- Состав и профили уточняются после пилотов ядра.

## 12. Сборка и поставка

### 12.1 Сборка
- Отдельный репозиторий `ofexcel` на основе DuckDB extension-template; сабмодули `duckdb` (ветка 2.0, как у ofquack) и `extension-ci-tools`.
- `extension_config.cmake`:
  ```cmake
  duckdb_extension_load(ofexcel
      SOURCE_DIR ${CMAKE_CURRENT_LIST_DIR}
      LOAD_TESTS
  )
  duckdb_extension_load(fusion_scanner
      GIT_URL https://github.com/<owner>/ofquack
      GIT_TAG <зафиксированный коммит>
  )
  if(COMMAND duckdb_extension_statically_link)
      duckdb_extension_statically_link(ofexcel fusion_scanner core_functions)
  endif()
  ```
- vcpkg: `openssl`, `cpp-httplib` с OpenSSL, `zstd`. JSON — вшитый yyjson. Parquet для обмена с `worker` (фаза 2) — встроенное расширение `parquet`.
- Вшиваются в бинарник: фронтенд (`addin/dist/*`), встроенные пакеты, примеры запросов.
- **`ofexceld`** — собственный `main.cpp`, слинкованный с `duckdb_static`:
  - `serve` — демон;
  - `worker` — процесс-исполнитель для недоверенных определений (фаза 2, §7.6);
  - `shell` — SQL-консоль автора пакетов;
  - `doctor` — проверка профиля, порта, CORS/сертификата, манифеста, входа;
  - `export-addin --base-url <…> [--bundle …] --out <dir>` — статическая надстройка для профиля hosted;
  - `install-cert` / `uninstall-cert` — только профиль local.

  Запасной вариант — переименованный shell DuckDB с `-c "CALL ofexcel_serve()"`.
- **Тесты:** sqllogictest (рендер параметров Oracle, токенизатор, валидация Local SQL, договор о типах, полная замена и инкремент, классификация ошибок, ключ кэша); HTTP-тесты в обоих профилях; сквозной тест на тестовом инстансе Fusion; нагрузочные тесты записи в Excel Table.
- **CI:** `osx_arm64` и `windows_amd64` (MSVC), сборка фронтенда до C++, подпись.

### 12.3 Установка
- **Демон:** macOS — подписанный и нотаризованный `.pkg` с LaunchAgent; Windows — MSI (WiX), Authenticode, задача автозапуска.
- **Надстройка, hosted:** IT публикует результат `export-addin` на HTTPS-хостинге и раскатывает манифест через Centralized Deployment.
- **Надстройка, local:** установщик запускает `install-cert` и регистрирует манифест для sideload.
- После установки — `ofexceld doctor`.

### 12.4 TLS (только профиль local)
Локальный CA (ECDSA P-256, name constraints на `localhost`/`127.0.0.1`) и сертификат на год через OpenSSL; установка CA в Keychain или `CurrentUser\Root`. В корпоративной среде (EDR, Intune, Jamf) установка своего CA почти наверняка встретит сопротивление ИБ — для неё предназначен профиль hosted.

### 12.5 Обновления
Новая версия — новый бинарник (ядро, ofquack, встроенные пакеты, фронтенд local). При несовместимом формате `data.duckdb` локальные datasets пересоздаются: это кэш, источник — Fusion. Проекты, наборы и книги не затрагиваются. Совместимость статики hosted с демоном — по диапазону версий API в `/v1/health`.

## 13. Серверный режим (фаза 3)

`ofexceld serve --mode server` на внутреннем хосте:
- хранение данных на сервере, а не на ноутбуках; Excel в браузере; обновление по расписанию;
- вход пользователей через Office SSO (Entra ID), сопоставление с `PER_USERS`;
- в Fusion — под сервисной учётной записью; **авторизация по каждому запросу каталога** и построчные фильтры пакетов на сервере — единственный режим, где потребителя можно ограничить сильнее прав SQL-отчёта без отдельных отчётов BIP (§8.2);
- отдельный разбор безопасности перед запуском.

## 17. Критерии приёмки MVP

| Критерий | Цель |
|---|---|
| Время от установки до первой обновляемой книги (пилоты) | Цель задаётся после фазы 0; измеряется на каждом пилоте |
| Сквозной сценарий §1.3 | Работает одинаково в Excel Mac и Excel Windows |
| Refresh реального AP-запроса на 100 тыс. строк, от кнопки до таблицы | Цель задаётся по замеру фазы 0 |
| Ошибка обновления | Таблица и dataset не меняются, видна ошибка и время последнего успешного результата |
| Отмена | Запуск останавливается не позже чем через 5 с; таблица не меняется |
| Повторный Refresh | Сохраняются имя таблицы, стиль, вычисляемые колонки пользователя, ссылки формул |
| Изменение схемы | В режиме `strict` таблица не меняется, показана разница колонок |
| Договор о типах | Идентификатор из 18 цифр — текст без потерь; `DECIMAL(18,2)` — без потери точности до записи; даты и NULL по §6 |
| Усечение | Всегда видно в панели и в истории |
